## Operations and exact bytes

- `POST /v1/memory-management-actions`, operationId `applyMemoryManagementAction`.
  Required bearer and `application/octet-stream`, identity content encoding.
  Body is original immutable UTF8 JSON with exactly five required keys:
  `action_id`, `operation` (`pause`/`resume`), `item_id`, `expected_version`,
  `expected_source_version`. IDs are nonblank original strings, <=4096 codepoints;
  versions are integers1..Int64max, never bool. Host max_body_bytes is explicit
  1..32768. Duplicates/extras/invalid UTF8/scalars fail. IDs/bytes are never trimmed,
  normalized or regenerated. There is no text/source/owner/approval input.
- `GET /v1/memory-management-receipts?action_id=<original action ID>`, operationId
  `queryMemoryManagementReceipt`. Exact single selector, newly valid current
  bearer and original host MEMORY scope. It calls only restricted ctx.query;
  no apply/retry, save-ledger query, source approval or new ID is inferred.

POST200 has required nonnull `{request_id, receipt}`; GET200 requires receipt but
allows null. Receipt has only `action_id,item_id,version,status,input_sha256`.
`action_id` is canonical Receipt.operation_id unchanged; status active/disabled;
positive bounded version; hash is the stored original action ledger bytes hash,
never a request-side substitute. Historical pause replay after resume returns its
old disabled/version receipt without disabling the now active item. Null only
means not observed in this scoped lifecycle ledger, never proof of noncommit or
permission to resend an unknown action. Ledger retention/tombstone is unresolved.
