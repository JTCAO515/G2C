The generic host metadata fields are not authority; type compatibility is not evidence a caller object was authenticated.

AeadCursorCodec requires that actual live owner context, compares its principal/scope to binding metadata before parsing/encrypting/decrypting, then re-reads the **same context object** and all metadata after crypto/clock. Missing/forged/expired context has no metadata-only fallback. Binding equality is never used as context identity. Next request constructs binding afresh from its own current trusted context. ## Primitive and exact opaque format

Uses existing pinned cryptography50.0.2 AESGCM with 32-byte host-provided key, fresh 12-byte OS-random public nonce and full library authentication tag; no custom cipher/MAC, tag truncation or default/generated runtime key. See [fixed-version cryptography AEAD documentation](https://cryptography.io/en/50.0.2/hazmat/primitives/aead/). Nonce reuse under a key is forbidden; host must set/operate key rotation and per-key usage policy before real deployment. Random nonce generation is not a persistent secret source and does not by itself validate production key operations.

Token: `version.key_id.canonical-unpadded-base64url(nonce || AESGCM_ciphertext_and_tag)`. Version and key ID are explicit nonsecret opaque ASCII labels, never derived from user/scope. No scope/principal plaintext is serialized in the envelope. Exact authenticated associated data binds protocol domain + version/key ID + current environment/issuer/subject/audience/scope/query kind/conversation. Associated data is not included in token bytes.

Encrypted payload has exactly generation, epoch, through, after, issued_at and expires_at. Scope/principal/query are not reconstructed from payload: after successful AEAD/binding/expiry checks, the internal Cursor/ChatListCursor is built using **current server binding scope/conversation**. Decoder never resolves a repository or selects a namespace. Unknown key/version, malformed/noncanonical base64, tag/cipher alteration, duplicate/unknown fields, wrong type/bool/nonfinite/int64/range, future-issued/expired/over-policy lifetime or wrong binding requires resync, never None/first-page fallback.

## Explicit configuration / rotation / bounds

All constructor parameters are required: immutable bytes keyring, active_key_id, version, clock, max_ttl_seconds, max_token_bytes, max_plaintext_bytes, max_binding_bytes. Keys are AES-256 only. Clock must return nonnegative integer epoch seconds; no time.time, skew or secret defaults. Per-call ttl_seconds comes from the explicit existing CursorPolicy and cannot exceed adapter max. Shortening current TTL can conservatively resync older longer-lived tokens; decode never extends expiry from now. Missing/malformed host configuration/provider clock makes adapter unavailable. Tokens are also bounded by API CursorPolicy caps.

Keyring is a frozen snapshot of explicitly provided active/old keys. Encoding uses active key only; old key IDs decode only while explicitly present. Unknown ID performs no file/network/JWKS/env lookup. Rotate by constructing a new adapter/config; removal/version change can resync existing tokens. No key persistence, KMS adapter, timer, issuer/profile switch, retention store or environment configuration is added. Do not print token/key/context or exception cause; fixed failures only. Live operations, durable key protection/rotation volume, clock correctness and revocation handling remain host work, not proven here.

Opt-in only: host constructs AeadCursorCodec and supplies CursorPolicy + HistoryWireConfiguration. Existing API default is still unavailable without explicit policy/limits; no default adapter activation. Public REST schema/paths/generated artifacts, source pins, root dependencies and domain code unchanged from2f8. The one internal context-reference field is the owner-confirmed compatibility delta.
