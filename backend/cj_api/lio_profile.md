# #926 internal planning profile

`lio_exploration_factors` is the fourteen-factor bilingual catalogue from #922
§3.1. Weights are static exploration/refinement/adjustment priorities, not a
mandatory questionnaire. Options contain ordinary send text; free text remains
supported. There are no nationality, age or exact monetary-budget questions.

`lio_exploration_profile` validates one `LIO-profile-update.1` model packet against
host-protected original MESSAGE text/MIDs. It is not a NEEDS schema or a write
capability. Only known/not_needed/inferred updates are model-selectable. Known
values are literal spans or canonical equivalents, refusals retain their quotes,
and inferred values cannot replace explicit facts, refusals or saved Memory.
Updates are ordered by original sequence/quote position, not model array order.

The internal `lio_planning_context.2` event records values, five states and typed
provenance. Message evidence uses genuine MID/sequence/quote/offset. Memory uses
actual slot/source ID/source version/item version/text, with no fabricated chat
MID. On every round Memory is rebuilt from the newly admitted capture; stored
memory/default projections never turn into user authority. Plain-text corrections
use the same extraction/merge path. No long-term Memory writer is called.

Code default proposals name the actual literal plan-now MID and fixed policy,
never a fabricated quote. Precise dates remain unset. They grant no permission:
WP4/WP8 must bind the actual selected native4 original and default policy to a new
protected SourceAuthority before any formal Trip publication. Refusal state is
retained separately while its effective planning default can be disclosed.

`local_lio_exploration_profile.ProfileContext` is an explicit host composition.
It re-reads originals only in the bound scope/CID/generation, keeps source anchors
outside the recent window and rebases Memory history fences on genuine message
references. The original worker event transaction holds RUN/reference/Memory
leases and rechecks mutable original hashes before committing context.2. Invalid
model evidence yields UNKNOWN; revoked/stale stored context yields context_invalid.
There is no retry or second model call.

No existing Lio factory installs this stage, and no API4 is admitted here. WP4
will select the new consumer and route profile edits before legacy itinerary edit
handling. Existing1/2/3 consumers remain unchanged. The L1 fixture explicitly
installs a private profile-only consumer over existing signed LIO3 transport;
this proves real MESSAGE/RUN/Memory transactions, not production native4 routing,
Trip signatures, supplier behaviour or App integration.

Validation: the registered `lio_profile` PG17 group runs ZH/EN two chains each,
real saved Memory prefill, ordinary correction/refusal/inference, actual pause,
bad quote UNKNOWN/zero profile, and a pause between capture and commit producing
context_invalid/zero profile. JWT/API/PG are real local components, extraction is
a fixture, model/tool calls and implicit long-term writes remain zero. L2/L3 and
native4 remain UNRUN until their corresponding integration and release gates.
