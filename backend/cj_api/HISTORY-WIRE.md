## Actual wire and same-context protections

Canonical OpenAPI adds GET `/v1/conversations`, GET `/v1/message-history`, GET/PUT `/v1/message-drafts`; only official generation changes Python/Swift types. Exact endpoint/input/projection/error details are in contracts/api/history-draft-proposal.md.

List/history/default unavailable: caller must provide limit; host must explicitly supply compatible max_page_limit (domain ceiling100, not product quota), positive draft/private-response bounds and, for pagination, authenticated codec + positive TTL/token bound. No default signing key, codec, clock, lifetime, quota, cursor store or retention is implemented. `history_configuration=None` leaves all four paths503; cursor_policy=None leaves list/history503 including first page, while configured draft operations do not need a cursor codec. Account registration/verification/recovery remain outside this restricted-business gate.

Only public `boundary.with_history_context(token, synchronous_callback)` is used for reads. Context principal and repository scope are captured together; no private _service, independent JWT/checker result splice, or caller-decoded scope chooses a repository. Codec authenticity/version/purpose/expiry and environment+issuer+subject+audience+scope+conversation binding are host responsibilities. API checks internal cursor exact type/scope/query and domain rechecks generation/epoch/high-water. Codec/read/encode/strict projection/fully serialized JSON/response byte bound all occur inside the same callback; owner same-principal/scope/facts check runs after it, then context expires. Return-stage failure withholds all private response fields. Timestamp claims are not storage/cursor identity; same identity/scope/query refresh can work within explicit policy. No authoritative session revision or atomic revocation guarantee is invented. Final AUTH guard does not revalidate data epoch after the read transaction; concurrent cleanup/late-data invalidation still needs the domain/DB fence and is not proven here.

All original bytes are immutable: PUT octet-stream is plain UTF8 draft bytes including empty; expected_revision mandatory. Output raw bytes are canonical base64 with strict round-trip and UTF8 validation, never reconstructed from text. Message history remains private; no raw/base64/text is included in BASE errors or partial results. Required nullable draft/next_cursor keys are always present. Generated fallback container must actually have nil value; arbitrary non-null fallback is invalid. Missing keys fail, not null/empty state.

Actual integer checks accompany int64 schema: epoch/list sequence, receipt sequence, revision; PUT expected_revision<=PG bigint max-1 before mutation, so increment cannot overflow. Duplicate/extra query parameters and malformed encodings reject, opaque strings decoded once without trimming or normalization. Draft input stream bound stops before full buffering, not only Content-Length. Read output-size failure returns413 safe-read; **after draft commit**, projection/UTF8/output-size failure returns503 unknown/reconcile_original, never400/fake rollback. Draft writes use owner's public save_draft outside the read-only context, retaining its own entry/transaction/commit/return guards; projection is synchronous and no stronger atomic authority guarantee is claimed.

Save does not emit message/run/delivery. Unknown save retains original generation/version/bytes; query original draft/revision, never message receipt. There is no durable draft-action journal or proof of submitter from same content/revision; stale revision conflicts and no blind retry/force overwrite is added. Null draft is only valid current chat/no saved draft; foreign/missing/inactive/stale contexts/denials/errors never become null or empty history.
