# Lio 分阶段冒烟与 #32 运行方案

按 [JT 11-10 决定](https://github.com/JTCAO515/G2C/issues/495#issuecomment-6755127810) 执行。当前状态为待 B 发阶段①就绪通知。本方案不认领批次。

## #702 分阶段冒烟

按 [陌生人任务清单](demo-v2-script.md) 运行，另补阶段①的中英事实问题。每条使用独立合成原消息。阶段②③的原件在同一已部署配置下串联，阶段①问答证据不替代保存与记忆证据。

| 阶段 | 本阶段分母 | 必须核对的结果 |
|---|---:|---|
| ① 纯问答 | 中英各 3 条，共 6 条 | 北京明日天气、故宫到景山的步行路线、下列官方事实来源。各条有完整正文及相关可打开的来源，日期、端点或官方出处对应实际工具结果，零 Trip 写入。 |
| ② 规划 | 中英各 1 条，共 2 条 | 北京三日行程自动保存一次，正文及行程卡对应已提交版本，首日酒店固定集合仍在。涉及拒绝、追问与日期归属的发布回归见 [PR717 用例](lio-pr717-regressions.md)。 |
| ③ 修改、撤销、记忆 | 中英各 2 条，共 4 条 | 第二天下午的改动单独追加版本，保留锁定项及其他安排，撤销追加新版本并还原内容。记忆候选出现时未激活，点击记住后在新对话实际召回，删除后新对话不再注入；若清理仍未完成，停止注入和物理清理分别判定。 |

阶段①补充事实问题：

- 中文：「在哪里能找到国家移民管理局关于 240 小时过境免签的官方说明？请给出来源链接。」
- English: “Where can I find the National Immigration Administration’s official guidance on 240-hour visa-free transit? Please link to the official source.”

三类问答分别绑定天气、地点及路线、事实的实际工具回执，记录服务观察时间、响应时点和正文来源。只核官方来源与正文是否有证据，个案资格保持未知。

## 开跑及停止

1. #702 的 B 通知需明确阶段、API/worker 源码及镜像、可测能力、合成账号窗口、来源和计量的只读核对方式。以现役签名部署和同版工作进程为准。阶段①无需 Trip 凭据；阶段②的配置由 B 按 JT 的范围处理。
2. 使用既有安全交接的短期合成身份和同一 HK ADOPTED 账本。开跑前保存只读账本行数、锚、旧 INTENT/UNKNOWN、候选版本、窗口和本批最大消耗。重新按当前授权条目 3/4 检查合计模型 ¥10,000、工具 ¥500、截至 2026-12-31 及地点/路线/天气/事实 1200/600/200/240 次上限。按完整回执估算加未完整保守占用预检，既有保守占用继续保留。历史批次预测不作为现役锚。资料不齐或越界则停派。 [M4 授权](../docs/authorizations/M4.md)
3. 用一个新 `message_id` 和原字节提交，从客户端单调时钟记录原始 HTTP 和时间线。超时或结果未知只读核原件，保留原尝试和原账。环境或判定程序失败经诊断后才用新运行 ID 复验，分别报告首次和复验结果。外部签名部署、身份、额度、工具续接或计量失败按原证据交给对应 owner。
4. 逐条归属原 RUN 和各实际 attempt，报告成功条数/计划数、中英分组、首个来自服务端的进度、首正文、完整结果及三栏费用。公域轮询错过进度时写 UNKNOWN；API 首见进度与 App 实际渲染另列。费用分保守占用、已知 token/工具估算及估算覆盖、供应商实付。无账单或归属不明写 UNKNOWN，失败耗用保留。

现有 C 采集分支的 [时间线采集器](https://github.com/JTCAO515/G2C/blob/117ed5ff3fe011aab73122a00b0f9ffdae10fca8/eval/lio_smoke.py) 可复用提交和轮询原件。该提交的阶段①报告模板只有天气及地点路线四条，需要按部署契约核好并纳入上述两条事实题后才出六条报告。阶段①收集不依赖行程或记忆写入。

## #32 六格

只在阶段①–③稳定、B 确认同候选交接且前置满足后启动。六格是进入正式批次的独立前置，另用新原件。用 [smoke.py](smoke.py) 的 `cases(today)` 冻结地点＋步行路线、天气、事实各中英一格。北京时间固定 `today` 后渲染同一组输入。此前脚本的本机/私有后端执行方式不是 Lio 公网执行入口。

| 六格判定 | 原件 |
|---|---|
| 所有格 | 签名 Lio 提交、原 MESSAGE/RUN 同一性、实测客户端时间线、同 RUN 完整非空正文、原 ACK 和账本。 |
| 地点＋路线 | 两地点原 POI 与坐标对应路线两端，距离/时长按查询时估算，来源及未知分列。 |
| 天气 | 北京日期、Asia/Shanghai、查询/报告时点及预报来源核同。 |
| 事实 | 官方 NIA 页的实际摘录和观察时点，正文仅援引所见，适用性按证据保持未知。 |
| 工具续接 | 原工具回执、native call ID 或相应注册绑定、下一轮实际模型输入及计量账本的哈希核同。展示来源或模型自报不能补这项。 |

实际运行串行。任一格失败、UNKNOWN、空正文、原计量或指定工具续接缺失，停止新派，其余格保持 UNRUN。仅同部署候选六格全部 PASS 且原件冻结可复核时进入 66。历史失败和旧批次认领保留，禁止借新目录或报告名重开原阶段。

## 正式 66 例

用 [scenarios.json](scenarios.json) 原样冻结 33 对中英案例、11 对留出、共 66 条，SHA-256 为 `2a5df582ee63f461afebe7a280cc5587e6281190f6aab05b458fa89f029d2e56`。冻结输入和独立 judge、分组、既有历史报告保留。开跑前做一份同候选的 recipe 到原动作映射，独立验证如下：

| 原 recipe | Lio 执行条件 |
|---|---|
| 普通问答 | 走签名 Lio 原对话，按原问题、事实及禁止副作用判定。 |
| 草稿、接受一次、拒绝 | 原草稿类保留零正式写入约束。需要 B 明确支持只读草稿/拒绝保存的同版路径，并能读回可核候选。接受一次须有原用户授权及恰好一个正式提交，精确重发时写入不变。Lio 自动保存若导致旧负例写入，按原约束记 FAIL；缺同版能力或证据时登记 UNRUN/UNKNOWN。跨版本映射若需要变更场景输入或判定，先与 JT 对齐并独立冻结追加版，留出样本不用于调优。 |
| 记忆 | 通过 Lio 的实际显式标签或管理动作取得原状态，核点击前未激活、保存后真实模型输入、新对话/重建/另一次旅行的实际召回、纠正/停用/删除后的不注入。同版路径缺失时保持 UNRUN。 |
| 硬项 | 开跑前检查独立程序能从原结果和来源提取 `short-trip/max_days`、`daily-budget/budget_limit`、`slow-pace/max_daily_items`、`transport-gap/verified_transfer_feasibility`。只有模型口头结论或无来源的文本时保持 UNKNOWN。 |

候选绑定精确提交、运行时配置、模型/工具与来源时点、样本指纹、计时端和账本。按境内开发 Mac + VPN 的真实提交路径和 [JT 新计时门槛](https://github.com/JTCAO515/G2C/issues/495#issuecomment-6708986558) 分组。中英各完成率 ≥90%、严重错误 0、App 首可见真实进度 p95 ≤5s、首正文 p95 ≤15s、完整 p95 ≤90s。单列 API 轮询观测与 App 计时，缺测不补值。既有旧门槛的历史 FAIL 保留。

正式数据齐备后给 JT 出双语人工审阅表，硬约束、事实和留出先排，附原问题、回复、来源、检查点、结果/严重错误栏和预计用时，判定留给 JT。按 #6 用同一批原回执复核实际会话用量、公开单价估算和供应商实付。#6 的内测模型 ¥400/用到 ¥300 停及高德出现扣费即停，与 #32 合成运行授权分开核对。 [#32](https://github.com/JTCAO515/G2C/issues/32) · [#541](https://github.com/JTCAO515/G2C/issues/541) · [#6](https://github.com/JTCAO515/G2C/issues/6)
