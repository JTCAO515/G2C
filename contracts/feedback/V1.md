# FEEDBACK@1.0

Frozen additive version for #15, compatible with the already generated
`FEEDBACK-WIRE@0.1.0-rc.1` submit/original-query wire. The rc document, schemas,
paths and old semantics remain unchanged. V1 freezes those exact fields and error
semantics; it adds no request `version`, owner, model metadata or reference type.
Existing generated `FeedbackAction/Receipt/SubmitResponse/QueryResponse` are the
compatible DTOs. A owns opening and wiring the App client and native evidence.

## Submit and reconcile

`POST /v1/feedback`, `Authorization: Bearer <current access token>`,
`Content-Type: application/octet-stream`. Body is the **exact original UTF8 JSON**
with exactly four keys:

| field | type / limit |
|---|---|
| action_id | ASCII `[A-Za-z0-9_-]{1,128}`; retain before first request |
| problem | nonblank voluntary text, ≤6000 UTF8 bytes, no NUL |
| expectation | voluntary text (may be empty), ≤6000 UTF8 bytes, no NUL |
| references | empty, or one `{kind:message,id:string}` plus optional matching `{kind:run,id:string}`; IDs nonblank ≤1024 UTF8 bytes, exact spelling |

Whole original body ≤16384 bytes. Duplicate/extra keys, malformed UTF8, run-only,
Trip/Memory/proposal/candidate references, caller owner/scope/version/tool/usage
facts are rejected. Memory-page feedback may submit **general feedback** with empty
references; it does not thereby bind a Memory item or authorize history collection.
Do not prefill transcripts/credentials. Voluntary text is never diagnostic authority.

`GET /v1/feedback-action-receipts?action_id=<original ID>` under the same account
returns the original receipt or explicit `receipt:null`. Foreign/absent actions
are indistinguishable. Null is an observed absence, not noncommit proof or permission
to mint a new ID. No automatic submit retry. After uncertain ACK keep the same
account/action ID/original bytes and use this GET; never reconstruct the JSON.

Same action and exact bytes returns the original immutable receipt. Any byte
difference conflicts, including whitespace/escaping. Query/replay does not reread
or replace the original source observation. It does not assert that source remains
currently accessible.

## Receipt and localization

Successful envelopes contain `request_id` and nonnull `receipt` (query may be null).
Receipt fields are exactly `action_id,input_sha256,submitted_at,status,message_en,
message_zh,source`. `submitted_at` is database UTC; `status` is only `submitted`;
messages are `Feedback submitted.` / `反馈已提交。`. No claim of repair, training,
operator delivery, service conversation or third-party dispatch.

`source` is required and null for general feedback. Otherwise it has only:
`message_id,conversation_id,generation,message_sequence,run_id,message_input_sha256,
run_status_at_read,event_highwater_at_read`. The hash identifies the original message
input, not receipt bytes. IDs and source metadata are verified through canonical
MESSAGE/RUN under the same fresh AUTH checker. No source text, tool payload, user
token or exception is copied into this object.

External model/rule versions, monetary cost, duration and provider-internal failure
stage are not inferred from these fields. Unavailable metadata stays UNKNOWN, not
zero or successful execution. #15's locator work separately exposes actual persisted
protocol/registered operation/stage/timing references; real provider details need
#32. It does not expand this frozen receipt or accept caller diagnostic metadata.

## Errors and lifecycle

401 missing/malformed bearer header; 400 grammar/unsupported fields; 409 exact-input conflict;
413 body bound; 415 media; 503 source/auth/storage/projection unavailable (including a syntactically valid bearer whose JWT/admission is rejected). BASE
`outcome/recovery` is authoritative: uncertain writes use `unknown/reconcile_original`,
reads `retry_safe_read`. Postcommit authority/encoding/connection failure does not
become failed-uncommitted or a fabricated success. No secret/private exception in
errors/logs; no-store and generated request ID apply.

Feedback stays until user/account deletion. The actual account cleanup hook must
erase `cj_feedback_action`, retain only an irreversible nonsecret scope fence, block
late insertion and return the original atomic result through CLEANUP. It does not
claim backup/device completion. #15 still requires restricted PG/FakeProvider and
A's real App composition/native checks; freezing this version is not that receipt.

Positive/negative actions: [positive](examples/v1-positive.json),
[negative](examples/v1-negative.json). Executable shape check:
`backend/feedback/tests/test_v1_contract.py`. Existing rc wire and generated consumer
checks remain required and unchanged.
