# NEEDS@1.0 — frozen

Owner B / CJ-013 (#14, #303), frozen under JT's 2026-10-30 standing authorization.
This is a new executable data protocol in `cj_needs.contract_v1`. The old internal
candidate version, original command grammar, HTTP schemas, protected-reader rc.2
and revision-lease@1 stay intact; none is renamed to imply new runtime acceptance.

## Public codec

| Call | Exact wire version | Domain result |
|---|---|---|
| `encode_command(Command)` / `decode_command(bytes)` | `NEEDS-command.1` | Validated original manual command |
| `encode_snapshot(Snapshot)` / `decode_snapshot(bytes)` | `NEEDS-snapshot.1` | Current record data, not freshness permission |
| `encode_revision(Revision)` / `decode_revision(bytes)` | `NEEDS-revision.1` | One immutable revision and its original command |

All encoders return UTF8 JSON bytes. Command envelopes have exactly `version` and
`original_input_utf8_base64`. Snapshot envelopes have exactly `version`, `needs_id`,
`revision`, `source_kind`, `content_utf8_base64`, `content_sha256`; revision envelopes
add exactly `action_id`, `original_input_utf8_base64`. Envelope limit is 524288 bytes.
Base64 is canonical RFC4648, padded; decoded original command/content limits are
each 131072 bytes. Duplicate/unknown keys, wrong versions, nonfinite numbers,
invalid UTF8/base64 and malformed domain content are rejected with `InvalidInput`.

`revision` is an integer 1..2^63-1; ID grammar is ASCII alphanumeric followed by
alphanumeric/`_.:-`, at most 96 characters. `source_kind` is only `user_provided`.
SHA256 binds the **exact** decoded content bytes, preserving whitespace/Unicode;
it is an association check, never a signature, ownership or currentness proof.
Content is the existing complete field map. No second lossy `fields` copy exists.
Each history original must match its needs ID, action ID, revision-1 and changed
fields; revision 1 must exactly equal its original changes. A later revision alone
cannot prove retained fields: consumers needing provenance must read/replay the
bounded full immutable chain and compare the final snapshot, as CJ035 already does.

## Fields and meaning

The exact field validators are the existing `cj_needs.domain.validate_fields` and
`Command` grammar, fully listed in [the original specification](README.md#command-grammar).
Their status as legacy candidate documentation does not identify this new wire
version. The fixed [V1 examples](v1-examples.json) are executable positive/negative
vectors for the new codec; old examples and constants remain unchanged.

- Observations are exactly `{state: missing}`, `{state: unknown}`,
  `{state: uncertain, note: text}` or `{state: known, value: ...}`. Absent is absent;
  no default party count, money, time, coordinate, permission or source is added.
- `party_size`, explicit destination/overseas IANA timezones, `pace`,
  `budget_currency`, decimal-string `budget_total`/`budget_per_person`/`budget_paid`,
  `budget_basis` (total/per_person) and explicit `budget_includes` remain distinct.
  Includes/excludes, international transport and already-paid amounts are user
  declarations; no conversion, subtraction, inferred coverage or implicit zero.
- `overseas_departure`, `arrival`, `departure` have date/time/timezone/place
  observations. Local date and wall time are retained verbatim; device timezone
  does not convert them. Ambiguous/nonexistent wall times need further evidence
  for an instant calculation; no solver/itinerary validity is asserted here.
- `companions` map local IDs to user labels. `fixed_items` retain unique item ID,
  kind (hotel/transport/appointment/intent), description, explicit `applies_to`,
  locked observation, booking_status observation and start/end events. Local
  companion references must exist in the complete resultant record. An order is
  a user claim, never a supplier verification. A lock intention is not silently
  relaxed by a machine. Explicit manual CAS corrections retain prior versions.
- `temporary_conditions` retain condition ID, subject and description for this
  record only. No preference, companion condition or new Memory is inferred.
- Original command is action_id/needs_id/expected_version/source/changes, source
  exactly `{kind: manual, text: ...}`. Omitted fields retain prior content; present
  lists/maps replace the complete field, and explicit empties clear it. Same
  original bytes replay the original receipt; same ID with different bytes
  conflicts. UNKNOWN always reconciles the original action, never a replacement.

## Authorized consumption and currentness

Call `ProtectedReader.read(token, fixed_projector)` under canonical AUTH to obtain
current data; encode it **inside** that lifetime. The projector can only detail/read
exact revisions. Missing, denied and unavailable remain distinct; no empty-success
fallback. Current-reader output alone is not global atomic publication permission.

For publication use the existing `CJ-NEEDS-REVISION-LEASE@1`, held across the RUN
commit under RUN→NEEDS→TRIP lock order. Compare the original captured needs scope,
ID, exact revision and content digest against current protected data. Do not hold
the lease during model IO; do not substitute caller-provided owner/hash/version or
an old successful read for the final canonical admission/currentness fence.
Travel selection must retain the explicit frozen MESSAGE-send.2 needs_reference;
old conversation selectors do not silently select a different record.

This PR publishes data and examples for C #281. Local runtime producer/HTTP
activation, extraction/correction combination, real accounts/model, FEAS solver
and App acceptance have separate evidence. The codec has no write/dispatch/Trip
confirmation capability and introduces no permissions, migrations or cleanup.
Retain old consumers/records during rollout; no automatic data rewrite or down.
