## 规范子范围

| ID | 必须遵守的规则 |
|---|---|
| N1 身份权威 | principal 只能来自服务端对新 CJ 环境的可信会话验证；客户端 owner/email/邀请标志、UI token、request_id、模型输出都不能授予权限。旧产品身份/缓存/权益不得隐式继承。 |
| N2 独立准入 | 首版邮箱密码、自助注册、邮箱验证/找回密码，JT 管理邀请名单。当前有效身份、已验证邮箱、服务端已确认的邀请资格是模型准入的独立必要条件；注册/验证/恢复成功均不替代邀请或资源归属检查。未知条件不授权。账号注册/验证/恢复不得因未邀请而被 MESSAGE 门禁堵死。 |
| N3 边界重核 | 受限业务的接收/查询/投递/恢复、引用及副作用边界须校验当前适用的身份、会话、资格和资源归属；异步等待后及派发/提交前复核，不复用过期准入快照。所有引用都检查；他人资源与不存在资源不泄露区别。接收 ACK 不授予模型执行权。 |
| N4 状态分离 | 邮箱未验证、资格拒绝、资格未知、登录拒绝、当前会话失效、链接失效、用户取消、网络未知必须在内部语义上区分。具体对外呈现仍须防账号枚举。网络/服务不可用不证明凭据无效；资源拒绝、链接失效或旧账号回调不得清除当前另一有效会话。 |
| N5 生命周期屏障 | 异步操作绑定原实例/账号代次/principal/会话有效性与原操作；退出、切号、新登录生命周期、明确失效使旧绑定不可回写。重登同一账号或重启不能复用旧生命周期；重复/乱序身份回调不能覆盖新结果。每次 await 后，在显示/缓存/持久化/派生工作前重核。 |
| N6 UI 与 AUTH 分离 | UI-local generation 只屏蔽旧投影，不能验证身份；host 同时校验 AUTH 绑定和原 UI token，不得取新 token 给旧结果重标。身份失效先关闭旧回写并清私有展示，再接新身份工作；语言变更不得改变身份代次。客户端清理不代表远端撤销、任务取消或物理删除。 |
| N7 未知与取消 | 未收到响应不等于未执行，资格拒绝/身份未知不等于原消息未接收。未知写入保留原动作，先对账，不换 ID/账号盲重发。用户取消只终止对应本地流程并失效回调，不声称撤销已发出的建号/邮件/密码修改；取消恢复不自动登出既有会话。 |
| N8 凭据与私有状态 | 密码、凭据、邀请秘密、邮件 token 与完整回调 URL 不进入普通日志、模型或 fixture。退出立即使旧私有展示/缓存不可读，安全存储清理失败显式呈现并阻止旧会话自动恢复；网络未知不误删有效凭据。远端撤销未知单独保留。 |

“受限业务”具体读权限划分未在本子版本固定。CJ009 当前保守拒绝未受邀历史读取
是草案策略，不把它发布为永恒产品权限；任何未来放宽必须明确独立读权限及消费更新，
不能放宽 N2 的模型准入，也不能通过本文件把普通账号恢复变成受邀专享。
N5 的会话有效性是语义约束，不要求某个 provider 拥有特定 revision 字段。

## BASE 错误与恢复的规范接缝（N9）

下表只约束语义与 BASE 既有枚举的对应，**不新增 code/category、HTTP 状态或路由**。
适用时未来正式 API 使用唯一 BASE ErrorResponse，真实服务端生成 request_id；
本地取消、transport loss 或 SDK 本地错误不得伪造服务端错误包/回执。

| 已核实的情形 | BASE outcome / recovery 的使用约束 |
|---|---|
| 本次受限操作在产生副作用前被明确拒绝：身份失效、邮箱未验证、未受邀、无资源权限 | `failed` / `do_not_retry`。意为不自动重复原受拒操作；用户完成验证、重新登录或资格改变后可显式发起/恢复，仍遵守原动作语义。 |
| 只读身份/资格/状态查询因依赖无法判定，且服务端有真实结构化响应 | `unknown` / `retry_safe_read`。仅许可安全读取；不得据此重发注册、邮件、密码更新或模型请求。 |
| 有副作用动作已发出，提交/撤销/邮件发送结果不能确认 | `unknown` / `reconcile_original`。保留原动作与绑定，先走后续领域定义的对账；BASE 不提供查询 endpoint，无查询能力时保持未知。 |
| 多部分动作中已有明确完成部分且另有失败/未知 | 只有存在真实分项证据时可用 `partial`；有未决副作用用 `reconcile_original`，确定失败且不应自动重复则 `do_not_retry`。不得把“本机清空”包装成服务端全局撤销成功。 |
| 本地取消或没有服务端响应 | 无可伪造的 BASE 包。按 N4/N7 保留本地取消与远端结果未知；是否可查原操作取决于原动作，不自动降格为 failed。 |

若动作先前已提交，不得因后续身份拒绝就将其原结果改为 failed/not_received；
此时上表 failed 仅描述本次被拒的读取/操作，不覆盖原动作账本。
密码修改、验证链接成功或恢复请求受理不属于业务授权成功，也不应伪装成错误回执。
未知 code/category 保留通用可见错误，不能授权；未知 outcome/recovery 枚举按 BASE
显式解码失败，不能当成功或重试许可。双语信息须安全且不泄露他人身份/资源存在性。

  正式 wire 类型；AUTH-draft.1 与本语义标识不互换。未发布的历史草案仍保留可追溯。
- 不固定 provider 验证/SDK/JWT claim、可信缓存/撤销时限、邀请名单存储与
  邮箱-principal 绑定/邮箱变化策略、回调域/路径/允许列表/跨设备恢复映射、
  正式 API/错误码/数据库/RLS/事务原子性、TTL/保留期限、离线缓存展示政策。
- 新环境资源/地域/费用/角色/回调待决仍见 EMAIL-DECISION.md。没有创建资源、
  扩权、凭据配置或真实账号授权；不接旧 VP 环境，不以规范候选关闭 Issue #8。
