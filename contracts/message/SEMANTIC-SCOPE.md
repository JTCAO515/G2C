# MESSAGE 语义子范围与发布条件

文档修订：`MESSAGE-semantics-draft.1`。本修订只收敛规范边界，不升级为
`MESSAGE@1.0`，不改变 fixture 输入版本 `MESSAGE-draft.1`。
实现/样例固定输入：`f43ad4d1ee8eec5126efa84a6f372ddcb66c0061`。
AUTH 核对版本：`f20393179333b9ed9a1e7055b5d18aade468833e` 的 AUTH-draft.1
及邮箱策略增补。RUN 无已确认固定版本。本文 normative 表示拟发布子范围内
消费者必须满足的约束，不表示已完成发布、生产实现或所有消费者确认。

## 三层边界

| 子范围 | Normative：必须保留的语义 | 内存 fixture 记法/证据 | 真实待实现与排除 |
|---|---|---|---|
| 原动作与输入 | 首次发送前固定原动作标识与完整原始字节；作用域含可信身份和操作种类；同标识同字节返回原回执，异字节冲突，不能重建输入或换 ID 消解未知 | receive、message_id、bytes 比较、SHA-256；17 场景中的原字节反例 | 正式 wire 编码边界、ID 格式、请求体限额、客户端安全持久化由 CJ005/009/010 确定；hash 不替代原字节 |
| 接收与查询 | 仅可靠提交后确认接收；原接收事实不随运行进展改写；未接收、已接收待处理、运行/结果必须可区分；消息接收不是记忆保存或模型派发许可 | immutable receipt 与 query 分开；accepted_pending/running/result_available 为合成名称 | 动态状态/终态正式结构由 MESSAGE/RUN 共定；本子范围不冻结枚举、字段或 endpoint |
| UNKNOWN 恢复 | 超时/断线保留未知，先查原动作；只有有权威完整账本支持的未接收结论，才允许原标识原字节有界重试；权限拒绝/查询失败/过期不是未接收 | LostAck 与 not_received/recovery_expired；无自动新 ID | 查询一致性、保留窗口、过期可识别机制、重试条件由 CJ005/009 定稿；不承诺无限恢复 |
| 投递义务 | 接收记录和稳定原运行投递义务不可出现提交后永久丢失窗口；恢复沿同 run；重复投递须由接收方去重，不凭 ACK 丢失另建运行 | 单次内存转换、jobs、runs、deepcopy image | CJ005/009 持久事务与恢复扫描；CJ010 原 run 去重和查询；不冻结 outbox/数据库方案，不声称 exactly-once 或重复付费已解决 |
| 分页 | 绑定身份与查询范围的稳定有序快照；重读可去重，追加不扰动原快照；无效/过期明确重同步，不能静默当空历史 | fixture-cursor 内存索引、snapshot、sequence、limit 1..100 | 生产 token/签名、存储/过期、页大小、撤回屏障未定；fixture limit/token 格式不是规范字段 |
| 结束与摘要游标 | 触发边界和来源必须可恢复；处理义务不依赖进程回调一次执行；先持久确认消费，再推进来源游标；未知 ACK 先查询，重投不得重复保存 | end_id + after/through，原消息/run 来源，durable_receipt 合成标志 | 显式结束后禁止继续原聊天是当前 fixture 提议，尚待 CJ020/产品确认；不冻结触发方式、批次形状或消费回执校验 |
| nullable Trip/草稿 | 不绑定 Trip 仍可聊天；意图不是 Trip 写许可；未发送草稿与接收/摘要事实分离 | null、consider_trip、内存 draft；非空 Trip 拒绝 | CJ015/016 确认正式 Trip 归属/版本/切换；草稿并发版本/离线策略尚未定；无假 Trip |

同聊天“前一个运行终态后才派发下一个”仅是本候选的保守串行策略，需 CJ010
确认后才进入发布子范围。顺序/取消/上下文有效性由 RUN 与 MESSAGE 联合确定，
不能以 fixture 的 opaque result 代替 RUN 终态契约。

## AUTH / RUN / BASE 接缝

身份来自服务端可信验证，邮箱验证与邀请资格独立。未验证、未受邀或资格未知
不能据客户端标志获得模型权限；身份/network unknown 不得当作未接收。
CJ007 对固定 AUTH 输入的语义消费已由 Main 转交确认；它不是完整 wire 冻结。
本模型对所有受限消息操作采用保守门禁，未受邀历史读取的最终范围仍待明确。
接收准入由 CJ007 可信裁决 + CJ009 资源归属 + CJ005 事务/权限共同实现；执行
准入由 CJ010 重核当前 AUTH/上下文，并由 CJ008 完成限额与预留。接收时快照
不得替代派发时及异步提交边界的重查。客户端晚到屏障由 CJ006/007/010 接入。

| BASE 恢复语义类别（不是新增机器码） | 消费者行为 |
|---|---|
| 输入/版本拒绝 | 显式纠正输入或升级；已提交原动作保持原字节，不能静默转换后重试 |
| 身份/资源拒绝 | 不泄露他人资源存在性；恢复当前会话或显示不可访问；不等于动作未发生 |
| 幂等冲突 | 保留原动作与回执，显示冲突；不能覆盖原记录或自动换 ID |
| 接收/投递结果未知 | 查询原动作/原运行；无法核实则保留未知，不盲重发 |
| 恢复窗口/游标失效 | 原动作不重发；历史分页按权威快照重同步，清楚区分恢复过期与空结果 |
| 执行/部分结果失败 | 展示原运行的已提交/失败/待核对部分，不修改接收事实、不假装回滚 |

正式错误必须纳入 CJ005 唯一 BASE ErrorResponse/request_id 入口。这里只确认
行为类别与恢复意图，不分配 HTTP code、category、retryable 布尔值或新错误字段。
无服务端响应不能伪造 request_id；请求追踪 ID 不能用作业务动作标识。
AUTH 完整 wire、RUN 事件/终态/取消/用量结构均明确排除，固定后另行消费验证。

## 数据与清理职责

| 私有数据/派生数据 | 领域责任与整合边界 |
|---|---|
| 聊天、正文、原动作字节、接收回执、草稿、投递义务 | CJ009 定义清单、归属、读取/清理 hook；CJ005 登记正式存储并落实事务/权限 |
| run 状态、事件/结果与执行义务 | CJ010 提供原运行查询、取消/失效和清理接缝；CJ008 管调用/计量恢复 |
| 结束边界、来源关联、摘要处理游标 | CJ009 保存可恢复来源/进度；CJ020 持久幂等消费及派生清理；CJ011 管正式记忆条目与版本 |
| 分页快照、缓存、客户端待恢复动作 | CJ009 与 CJ010 客户端消费方定义留存及代次失效；CJ006/007 提供账号切换屏障 |
| 全域撤回、注销、备份恢复 | CJ024 协调全部 hook 与撤回重放，CJ005 维护存储登记；任何旧投递/摘要不能使已清理数据复活 |
| 诊断引用 | CJ023 只取必要关联；正文、密码、token 不进入诊断或模型日志 |

上述为生产责任分配要求，不宣称 hook/存储/备份已实现。保留期、物理清理时限、
备份撤回重放和过期 ID 防复用方案未定前，不得以本子范围放行真实持久化验收。
