# CJ-022 offline snapshot candidate v1

Scope: isolated format/codec, private atomic file primitive and pure validity evaluator. No App factory, new key provider, live cache path, wire route, offline write queue, or Memory writeback. Issue24 stays open. Source base `8deb696f8149b4f5aa70c767be6c3a263b036227`.

## Source and format

Only official `Components.Schemas.TripDetailResponse.TripRecord` from canonical c02 CJAPI is decoded. Module-internal capture validates request_id, exact response/record/document shape, duplicate keys, IDs, unique items, original UTF-8/base64, document equality and positive version. It preserves complete response bytes and exact canonical content bytes; it does not regenerate content. Proposal/null/unknown fields/malformed documents fail. This is structural validation, not proof of server acceptance: existing TripClient.detail returns a typed record without raw response bytes. The trusted accepted-response byte hook is now supplied by Trip owner 2b299 and consumed internally by AcceptedDetailSnapshotCache; original session/selection validation remains with that owner. It does not grant offline access. No public capture/seal/open/store constructor is exposed. No public plaintext property is exposed.

Envelope v1 is JSON {metadata,ciphertext}; ciphertext is CryptoKit AES.GCM combined nonce/ciphertext/tag (random nonce per seal), 256-bit key. Direct SymmetricKey injection is an internal isolated-test seam; the new module-internal CanonicalSnapshotAccess obtains material only through canonical MessageEncryptionKey.withSymmetricKey. Sorted JSON encoding of *all* metadata is AAD: format, exact canonical source pin, account/backend/trip, formal version, syncedAt/deadline, boot/uptimeAtSync, original response/content SHA256, and expected keyID. Unknown format/source fails with no legacy fallback. Hashes are checked after authenticated decrypt. Decode never tries another key/version. Maximum response 2 MiB, envelope 4 MiB; these are local format bounds, not server contracts.

Rollback rejection requires an authoritative caller-supplied minimum formal version; a self-contained encrypted file cannot detect replay of an older valid file without an independent anchor. The evaluator requires positive minimumVersion. This module does not invent a persistent AUTH anchor or grant offline authorization.

## Files and unknown writes

The store opens every absolute path component using directory descriptors and O_NOFOLLOW; it does not resolve attacker symlinks. Callers supply an existing physical path. Test directories are new 0700 directories under realpath(NSTemporaryDirectory). It rechecks root device/inode/owner/mode before/after operations, rejects symlink/hardlink/nonregular/oversized/empty/non-0600 entries, bounds reads and detects named-file replacement and size/mtime/ctime changes. Writes use unique O_EXCL 0600 temporary files, full write+fsync, renameat and directory fsync, then exact-byte readback. Only ciphertext reaches disk. No recursive cleanup.

After an uncertain rename/fsync/readback, the same store retains original and attempted **ciphertext bytes**. New writes/clear are blocked. Reconciliation reads the fixed entry and compares with those original bytes, returning committed/originalRetained/unknown; it never reseals or restores old bytes. Process-crash durability of an unresolved operation receipt is not claimed. A same-user compromised process can race file operations; inode checks/authentication detect observable changes, not malicious-OS control. Local clear removes only this entry; it is not global logout/remote/device cleanup. iOS protected-file class and device-lock behavior remain unintegrated/unverified; no production cache is enabled.

## Validity and product gates

No TTL default. Policy absence/invalidity => unavailable. Sync time and authenticated deadline are explicit; effective deadline=min(snapshot deadline,sync+configured maximumAge). Equality with deadline is stale. Integer overflow, future sync, absent/untrusted time, wall rollback, invalid uptime, same-boot uptime rollback, absent last trusted time, wrong account/backend/trip, stale formal version or session denial => unavailable. Same-boot elapsed monotonic time can expire a snapshot even when wall time stalls. Reboot permits evaluation only with fresh host-trusted wall time and last-trusted anchor; system wall time alone is not such authority. Host must recheck current identity/session/selection after async work and immediately before display. Larger future policy cannot extend the snapshot's authenticated deadline. Results only evaluate supplied policy/clock; they do not authorize offline access. Public result carries version/syncedAt/deadline or stale/unavailable; both languages refer to the same snapshot, no regenerated translation.

## Canonical key consumer delta after 24221

`CanonicalSnapshotAccess` consumes the original final `ScopedMessageKeyProvider`, `MessageEncryptionKey`, `SessionLifecycle` and captured `SessionOperation`. It only calls begin(.lookup)/existing(expectedID:), never create/clear/reconcileCreation/rotate. The full existing metadata JSON AAD is unchanged; withSymmetricKey encloses the codec AES-GCM primitive, without a second key store or public raw-key constructor. The exact dedicated purpose is checked together with account/backend before lookup and after callbacks; expected key ID is mandatory and checked against both the provider result and snapshot metadata. No new public wire/App interface is exposed.

Every read preserves original ciphertext before key lookup, validates source/session/provider operation after the last external source callback, then compares the exact original file bytes using callback-free primitives before returning an internal snapshot. A changed file/key/session/source fails without returning content. Writes retain the original pre-callback bytes and cannot overwrite callback-replaced files. Reentrant operations on the same access object are refused. An unresolved file write blocks reads and writes **before key lookup/sealing**; only original-byte reconciliation is permitted, and unavailable/unknown keys cannot settle it. Reconciliation never reseals, restores, or mutates the file.

The source UUID supplied here is only a host lifetime fence, not an accepted-Trip proof or a proposed signature for the pending TripClient hook. Correct source invalidation must be propagated by the host; key-provider current-operation checks do not promise detection of arbitrary out-of-band OS/Keychain tampering. SessionLifecycle.isCurrent proves local operation currency only, not offline permission. Policy/trusted clock evaluation and the true accepted-source hook remain required before any App output, and `appFactoryAvailable` remains false.

Auth prep is one unchanged original file from `4eac0ad8db0ac33c89c7cc5b88d66b58d0fd6a7e`, recorded in evidence/auth-key-prep.json; all other AUTH source and Package.swift already matched that head. The local package lock adds existing AUTH transitive dependencies; shared/root locks and packages are unchanged. Tests inject only in-memory persistence into the actual canonical provider and session; they call no SecItem/keychain factory or AUTH failure probe. The one initial test-macro compile failure is retained in canonical-key-initial-compile-fail.log.

Internal `AcceptedDetailSnapshotCache` accepts only an `AcceptedTripDetailSnapshot`; it cannot construct or relabel that handle. Its synchronous read-only closure preserves the exact original response Data/trace and builds the encrypted-format candidate without provider/filesystem side effects or response reencoding.

The caller prepares the original request synchronously, awaits the one existing detailSnapshot GET, and then constructs this capture. The constructor and write entry revalidate the original sealed handle; canonical-key access retains it as the source guard, revalidating after provider callbacks and immediately before/after store settlement. The final guard is followed by concrete session/provider checks and exact callback-free original ciphertext comparison. A new selection/source, session operation, legacy invalidation or callback replacement cannot relabel old content or overwrite a replacement file. Each capture permanently reserves its one write attempt before the external source-validation callback (even if that validation fails); unknown file writes block even a new capture before source extraction, lookup or nonce generation. Reconciliation uses the original retained attempted ciphertext, with the same original handle/key/session guards, without a new GET, reseal, restore or resend. A source retired after rename withholds success; existing ciphertext is not silently rolled back or claimed absent.
