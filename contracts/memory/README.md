Internal Python domain/repository only. NOT MEMORY@1.0 public-wire freeze. Root OpenAPI, generated clients and migration registry remain CJ005-owned. Source baseline: 23e12f28435ab0ddc685d544670564e3fa79db41. AUTH composition decision remains existing `AdmissionDecision`; MESSAGE/RUN scope is the existing trusted internal partition concept, not a new principal schema. Concrete consumer acceptance via Main is pending.

`Command`, `Receipt`, `Item`, `Context` live in backend/memory/cj_memory/domain.py (one executable source, no shadow model). `Service.save(original_utf8)`, `query(operation_id)`, `groups()`, `list_items(after, limit)`, `detail(item_id)`, `effective(subject, context_id)` are the minimal consumer interface. Commands are strict exact-key UTF-8 JSON (positive/negative examples in examples.json); no owner field. An operation ID belongs to one scope and save operation; byte-for-byte replay returns the immutable original receipt, different bytes conflict. A receipt is historical saved/candidate status and version, not proof the item is still effective. query absence does NOT prove an unknown original operation never committed or authorize retry after retention/cleanup. No automatic retry exists.

## Trusted composition responsibilities (required before public use)

- AUTH composition reuses `backend/auth/cj_auth/interfaces.py` and `admission.py` (`CJ-AUTH-SERVER@0.1.0-rc.1`), injecting the existing verifier and unique CJAccessProvider; no copied types, allowlist or authorization logic. Only a fresh ALLOWED decision carrying TrustedPrincipal may enter. Bind stable scope to approved environment/profile plus trusted issuer/subject; verify audience, never partition by iat/nbf/exp. Recheck admission after awaits, before commit and before returning private data. DENIED/UNKNOWN returns no private content and initiates no further effects; generic denial must not distinguish another user resource from a nonexistent one. Admission does not authorize source/resource references: domain source ownership/version/withdrawal checks remain required. If commit may have happened, preserve original operation and reconcile_original rather than declaring no write. This module neither authenticates nor provides public source registration.
- AUTH owner confirmed these consumption semantics via Main on 2026-10-22, against main23e source; this is read-only interface confirmation, not live authentication acceptance. Existing AUTH has no real-time session revocation version or atomic cross-transaction AUTH guarantee. A cached ALLOWED decision or still-valid JWT does not establish either. Current memory scope/source/item fences cover data consistency only; true account fencing and API composition remain unimplemented integration requirements.
- Source approval is explicit, exact-byte-bound `cj_memory_source`: owning scope/source revision, approved bytes, authorized/confirmed/semantic_resolved/active, explicit expiry. Trusted composition checks source provenance (manual save or exact MESSAGE generation/message), subject ownership, applicable context/trip ownership, purpose and consent/time/retention. Missing/unknown sensitive collection approval means **no approval row / reject**, not an inferred default. Table booleans cannot come from client flags. Schema does not provision any scope or source.
- `subject` and `slot` are canonical references checked by composition; one stable slot across languages, never a translation-derived ID. Unresolved equivalence sets semantic_resolved=false, saved as candidate only. Existing active same subject/slot/extent/context conflicts; user reviews the existing item for future CJ019 versioned change. Arbitrary new slots must not be minted to evade this check. No translator/model or semantic equivalence detector is claimed.
- `inference` is always candidate in this first create path, even with confirmation flags. A confirmed inference requires a reviewed concrete fact/experience/preference representation; no automatic promotion.
- `extent=current` requires an explicit server-validated context identity (include generation where relevant); it overrides only matching subject/slot while composing that context. Other contexts see the unchanged long-term value. Companion subject is never silently self.
- Source expiry is explicit, not a retention-policy default. Approximate occurred_at is supplied display text; recorded_at is DB time. The local tests use synthetic one-hour approvals ONLY, not product retention policy.

## Transaction and subsequent lifecycle seams

New fresh non-autocommit DB-API connection at READ COMMITTED per call. Scope lock serializes operations and future mutations; item+receipt+epoch increment commit together. Commit exception is CommitUnknown, even if it failed before committing, because the caller lacks proof. Query the original operation. Cleanup failure cannot mask a durable receipt. No ReMe/derived component is authoritative.

CJ019/021 must take the SAME scope row lock; compare expected item version and source revision, increment item version and scope epoch, and atomically write their own original action receipts. Revocation must disable/increment source as appropriate and update scope epoch. No public edit/delete/enable implementation is supplied here. Source history/retombstones and full deletion lifecycle remain required before those features can ship.

Every effective read joins current source revision, authorization, confirmation, active flag and expiry, excludes candidate/disabled/withdrawn items, and returns scope epoch. Before RUN publishes an answer it must use `Transaction.require_current(context, subject, context_id)` and retain that transaction/scope lock through publication; cross-domain adapter must share that transaction. `Service.check_fence` is only an epoch probe, NOT publication authorization: expiry passage also invalidates context. No existing RUN publication path is connected by this candidate.

List uses bounded (1..100) live item-ID keyset pages, not an immutable snapshot; groups aggregate subject/status. Detail exposes source ID/version, text, scope of applicability, type, occurrence display time, DB record time and item version/status. User-facing bilingual labels are a UI responsibility and do not create authoritative IDs.

## Additive request guard seam — MEMORY-internal.1 consumption increment

CJ005's public request entry is now **`Service.with_operation(guard, operation) -> bytes`**. No API consumer needs to access the repository or wrap its transaction. The original direct `save/query/groups/list_items/detail/effective` methods remain compatible for trusted domain tests/internal composition only; they are NOT authenticated HTTP entry points. Do not expose them directly from a route. The compatibility path remains until CJ005 is confirmed to consume the guarded seam, then a separate coordinated change may narrow it. No root API/schema change is made here.

Both callables come from trusted host composition, never caller wire. `guard(stage)` must invoke existing `AdmissionChecker.check` freshly, require `AdmissionStatus.ALLOWED` plus the existing `TrustedPrincipal`, and return `(principal, server_scope)`. DENIED/UNKNOWN must raise or return no binding. The service validates the exact TrustedPrincipal type and compares the entire captured principal and repository scope on every stage; no copied AUTH type/policy or client owner binding exists. Host module search path includes existing backend/auth plus backend/memory.

`operation(context)` is synchronous and returns fully encoded JSON **bytes**, prepared inside the callback. Context exposes only `save(raw)`, `query(id)`, `groups()`, `list_items(after=None, limit=50)`, `detail(id)`, `effective(subject, context_id=None)`. At most one save is permitted per context, so reconcile refers to one original operation. Context expires on every exit, rejects another thread, and must not be retained/reused. Coroutines, generators, iterators, functions, context objects and other non-bytes callback results are rejected. Trusted callback must not stream/send/cache private data itself; return the encoded bytes and let the host publish only on successful completion. Python cannot sandbox an intentionally exfiltrating trusted callback.

Exact stage sequence for one DB method: `entry → transaction → transaction_ready → domain work → precommit → DB commit → private_return → callback projection/encoding → return`. `precommit` is **inside** the repository transaction, after domain SQL and before its commit; rejection/UNKNOWN/identity or scope change raises through the context manager and rolls back. A fresh entry check also runs for callbacks that never access the database; final guard follows all projection/encoding. Guard failure is sticky for the context, even if the callback catches it.

`OperationWithheld` from `cj_memory.operation` carries trusted-only `stage`, `operation_id`, `commit_possible`, `recovery` (generic exception text contains no private content). If a save reached commit attempt, commit ACK is lost, postcommit guard fails, or projection fails after commit, no result bytes escape and recovery is `reconcile_original`; preserve the caller's original operation and query under newly valid AUTH. Do not translate this into "not saved", generate a new ID or auto-resend. A precommit denial has commit_possible=false for this attempt, but is **not** proof that a prior attempt with the same operation did not commit. Read-only denial withholds the response without claiming a write. Metadata remains inside trusted composition, not an authorization-error leak to a changed principal.

The seam is synchronous; async work must finish before entering or after it returns, never inside the callback. Host must use a new call/context after any await and must not defer JSON serialization until after the final guard. This narrows in-process timing gaps but does not claim realtime session revocation or an atomic distributed AUTH+database transaction. RUN data/source publication fences remain separately required as above. Source approval still has no public writer.

### List consumer confirmation

Public Service/context `list_items(after=None, limit=50)` guarantees live item-ID keyset ASC with integer limit 1..100. SQL explicitly uses `COLLATE "C"` for both strict `>` comparison and ORDER BY; candidate item-ID columns also use C collation for exact equality/uniqueness. UTF8 database encoding is required. Order is lexicographic UTF-8 bytes, not localized alphabetic ordering. IDs are opaque exact strings: preserve case, whitespace and Unicode normalization form; do not normalize, case-fold or compare in Swift String canonical-equivalence semantics. The consumer simply passes the exact returned ID as `after`.

CJ005 can emit `next_after = items[-1].command.item_id if items else None` for each page, including a short nonempty final page. This is a continuation anchor, **not has-more**. An additional empty read at the end is expected. Pages are live, not snapshot-isolated across calls; concurrent insertions before the anchor are not promised in the current scan. Do not infer full inventory consistency. No private repository access is needed. Existing internal.1 scope, authority and public-wire ownership remain unchanged.

### Exact Service binding invariant (CJ005 confirmation)

At every guard stage, `with_operation` requires (1) fresh guard scope equals the captured repository's current scope, (2) guard tuple equals the original `(TrustedPrincipal, scope)`, and (3) Service still references that same repository object. Thus wrong-Service binding is rejected at entry before callback/connection; scope drift cannot rebind even if both the guard and repository switch to B; replacing the repository with another instance is rejected even for an identical scope. Context expiration remains enforced. CJ005 may rely on this public behavior and does not need `Service.repository`, a new wrapper, or a bound_scope accessor. Host must not mutate request services concurrently; this is an in-process boundary check, not an atomic distributed authorization guarantee.
