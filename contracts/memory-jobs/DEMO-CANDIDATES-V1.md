# Demo v2 memory candidate publication

Server-only C interfaces for the selected internal assembly in [#702](https://github.com/JTCAO515/G2C/issues/702). B selects the trusted subject roster and owns the source scheduling, registered Meter, dispatch, and public event envelope. The C interface adds no route or account grant.

- `DemoCandidates.processing_policy` and `publication_policy` take the same original foreground `message_id` and `run_id`, in B's live `HistoryReadContext`. An incremental source must contain exactly that one committed message. The existing source, owner, authorization and final commit guards still apply.
- A valid `MEMORY-EXTRACT@2` output can contain multiple entries. Only `long_term` `fact` and `preference` entries produce canonical **candidates**. No extracted entry can authorize confirmation. The complete original output and its digest remain immutable, including filtered entries.
- The new historical receipt version is `MEMORY-PUBLICATION-result@4`, with the same envelope fields as `@2`. The `receipts` array contains only the eligible entries, in original order, each with status `candidate`. A mixed preference/experience output yields one preference receipt; an output with only a current preference yields an empty receipt array. Original `@1`, `@2`, and `@3` consumers retain their own explicit versions.
- B reconciles this version using `DemoCandidates.query_publication_in_context` with the original job, attempt, message and RUN. A wrong RUN, another owner, or a legacy receipt version is withheld. For the live card, `DemoCandidates.current` returns only eligible pending records for that original message, with the original review IDs and current Memory epoch.
- Remember and Dismiss use the existing signed `MEMORY-CANDIDATE@1` confirm/reject action and its original receipt. Historical publication proves that a candidate existed and grants no authority to activate or re-create it after rejection, withdrawal, or deletion.
- The existing item erasure freeze validates and includes the original `@4` receipt without changing the evidence envelope. The canonical stop and original source fence exclude the item before the physical cleanup finishes. B must consume `@4` explicitly in its new Demo assembly and retain its original attempt and cleanup proof.
