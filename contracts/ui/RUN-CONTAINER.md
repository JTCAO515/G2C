# CJ006 original RUN display/read-only recovery container

This consumes the scoped RUN display slice of [CJ010 / Issue11](https://github.com/JTCAO515/G2C/issues/11), whose original body was read via official GitHub repository ID1428033587. It does not complete streaming, server stopping, worker/provider, real model/account or App/device/I requirements.

## Exact accepted MESSAGE source

MessageHTTPClient already validates the generated MessageReceipt against the original staged/unknown MESSAGE and persists `JSONEncoder().encode(receipt)` through canonical MessageRecovery.observeReceipt. ActionRecord.receipt is deliberately opaque transport-verified Data. The previous CJShell had no typed accessor for that current selection.

`AssistantMessageHost.captureAcceptedRunReceipt()` now decodes that exact stored payload as the official generated MessageReceipt. It requires current original binding/lease, an explicit message selection, accepted phase, byte-exact message ID, receipt input hash equal to the canonical original-byte digest, and unchanged canonical ActionRecord after the trusted binding callback. It captures a private selection revision before callbacks and rechecks it afterward. The resulting AcceptedMessageRunReceipt has no public initializer, no mutable IDs and redacted description/mirror; it is linkage/ownership evidence, not authentication or RUN-creation authority.

MESSAGE bind/action selection, draft selection, receipt query and retirement synchronously retire the old RUN selection before later work. Draft selection does not alter existing MESSAGE recovery state; it simply cannot masquerade as an accepted RUN source. Canonical query completion enables a newly checked accepted selection. A source revalidates exact current original bytes/receipt and original MESSAGE lease every time. No receipt is manufactured from UI text, arbitrary message/run IDs, staged actions or decoded JWTs.

## Root configuration and foreground lifecycle

The trusted root constructs the existing bounded RunDisplayModel with MessageEndpoint, NoRedirectTransport and its accepted async credentials callback. RunContainerConfiguration supplies that model, the same canonical SessionLifecycle/original SessionOperation, ShellGeneration and current admission callback. No second identity/provider/permission/queue/key/store is introduced. AccountHost exposes committedSessionOperation, but its session/verification are private and it does not expose a public bearer accessor; CJShell therefore receives the already configured model and never reads raw session bytes or invents an automatic credential bridge. Real endpoint/credential/root composition remains unconfigured by default.

Configuration creates no source and performs no request. While visible/active, the user explicitly selects the current accepted message, then RunDisplayView synchronously calls prepareRead before Task.perform. Source ownership combines captured configuration/selection, original MESSAGE source, original session operation, trusted admission and foreground. Validation is bounded: check current admission, invoke the original MESSAGE validation, recheck admission, then finish with callback-free original MESSAGE lease/record, selection, configuration, session and foreground checks. The final ownership read is not admission or a new authorization provider. Thus the MESSAGE callback cannot leave an earlier admission result usable, and the final admission callback cannot silently retire/replace the original source. Canonical model epoch checks retain responsibility for preserving newer prepared work. Prior source is invalidated before selection callbacks. If canonical select returns false because a newer prepare won inside a callback, the host does not clear that newer work; canonical model owns its settlement.

Account/environment/root invalidation clears configuration and source. Message/source changes, view disappearance, background or inactive phase clear only private source/display state and retire queued work. Foreground reappearance never reselects or reads automatically: an accepted original must be explicitly rechecked and selected. The old model/work cannot adopt a new selection/account or publish late text. Language changes preserve the same selected model.

## Presentation and recovery semantics

The existing Assistant scroll flow embeds public RunDisplayView; no new Tab. Seven canonical statuses, partial/complete text and unavailable states are used directly. Text is rendered verbatim. Selecting original RUN mode hides the prior plain answer and its old Feedback association instead of appending a second answer or treating that body as fallback after a failed read. It does not automatically bind the RUN snapshot to a different Feedback source; such linkage needs trusted root composition.

Only official GET getRunDisplaySnapshot with the exact original message_id is issued. Reads neither persist/update MESSAGE receipts nor stage another action/run. No SSE/polling, stop request, provider execution, new identifier, resend, fake queued record, fallback body or inferred tool success. Completed requires actual complete snapshot semantics; other states remain partial. A returned snapshot is an observation at read time, not a guarantee of latest/distributed state. Failed reads are unavailable and do not publish old private comparison bytes.

Default missing root/source is visibly unavailable. Original receipt/source and diagnostic/reference values are not logged or persisted by the new container. All existing product write gates remain closed.
