## Public cursor and configuration (explicit host capability, otherwise unavailable)

Internal Cursor/ChatListCursor is not a public token and cannot be built from caller JSON. Proposal requires a host-injected authenticated cursor codec, explicit positive TTL, token byte bound and per-route maximum page limit; API `limit` is required (no invented default20). Max must fit current domain hard guard1..100, which is an implementation ceiling, **not an approved product quota**. Draft/read-output/body byte bounds likewise explicit host configuration; size failures use BASE, request body is bounded while streaming, not only Content-Length. Missing required cursor codec/policy leaves list/history unavailable including first-page requests; draft routes have their own required limits and need no cursor codec.

Codec validates authenticity, version/purpose, expiry and bound current trusted environment/issuer/subject/audience/storage scope and query conversation before returning internal cursor; it may not use decoded caller scope as authority. Internal generations/epoch/high-water remain domain-validated after decode; old/recreated/other-user/other-query tokens require resync, not silent empty page. Expiry/rotation/freshness policies belong to explicit host injection; no secret/default signing key/TTL/retention is selected here. Codec output size/type also checked before release.

**Precise seam needing CJ009 confirmation:** current public Boundary returns rows/cursor but not the trusted repository scope needed to validate a public token. Prefer a single server-only `boundary._service(token)` authorization/resolver call, then take scope from that service's GuardedRepository, bind codec to this trusted context, and invoke actual Service methods so existing transaction/commit/return checks remain. This is private API consumption and is PENDING explicit owner acceptance; alternative is an owner-defined trusted context seam. Do not decode a cursor to discover which repository to resolve. Codec execution cannot bypass current AUTH/resource checks; failures withhold all private content. A final fresh same-principal gate after codec/projection is needed before private response publication; this remains synchronous fencing, not atomic distributed revocation.

## Draft unknown / integrity and BASE mapping (proposal)

Draft save never creates message/receipt/run/delivery. Same text is not an action identity: unknown save retains original id/generation/expected_revision/bytes, then reads the original draft/revision; matching content or revision alone does not prove which writer committed. No idempotency journal or automatic retry/force-overwrite is invented. Stale expected_revision InputConflict is409 failed/do_not_retry, not a blind overwrite. No DELETE/clear-on-empty API; empty UTF8 is an explicit saved draft.

All existing receive/query semantics unchanged. Reuse401 invalid identity,403 generic denied, entry/transaction-entry UNKNOWN503 unknown/retry_safe_read; commit/return uncertain effects and CommitUnknown prioritize503 unknown/reconcile_original. For draft unknown, reconcile_original means original draft/version read, not message receipt lookup. Invalid query/body/UTF8400; byte bounds413; wrong media415. ResyncRequired and authenticated codec invalid/expired/wrong binding →409 `HISTORY_RESYNC_REQUIRED`, failed/retry_safe_read (new first-page safe read, never write retry). Codec/TTL/host dependency absent/unavailable →503 unknown/retry_safe_read. Domain Unavailable for foreign/missing/inactive/stale context remains generic503 (no existence/ownership disclosure), never null/empty private history. No token/principal/reason/body leaked in BASE errors.
