# G2C 七城重点 POI 候选库（2026-11 第一轮）

本目录存放北京、上海、广州、深圳、成都、重庆、桂林七城的第一轮重点 POI 候选，全部标记为 **待复核**。它是候选资料，不是已确认事实：不得直接进入 Lio 回答、FACT wire、GitHub Pages 事实快照或任何正式消费者。晋级流程见文末。

与既有候选区的关系：广州/深圳 2026-11-18 的景点、餐厅、酒店、商店候选保存在上一级目录的 `2026-11-18-*.json`（`visitor-place-candidate.2`，PR #1200/#1204/#1206），本目录的广州/深圳 CSV 以该批为底稿，按本目录统一口径重新归类、补充街道街区和商场市场、补齐中英文名，并增加七城一致的列。两处可并存，后续查重时以本目录 CSV 为准合并；本目录不修改既有 JSON。

## 列定义

前 16 列为必填列，顺序固定；缺失值明确写“未知”或“待补充”，不猜测。

| 列 | 规则 |
|---|---|
| `row_id` | 稳定候选编号：`BJ/SH/GZ/SZ/CD/CQ/GL-0001`；同城唯一，追加记录时顺延，不改旧号 |
| `city` | `北京`、`上海`、`广州`、`深圳`、`成都`、`重庆`、`桂林` |
| `district` | 区县全称（如 `东城区`、`阳朔县`）；无法确认写“未知” |
| `category` | 一级品类，只能取：`餐饮`、`酒店住宿`、`景点与文博`、`街道与街区`、`商场与市场` |
| `subcategory` | 二级品类，取下文受控词表；七城同一概念使用同一名称 |
| `name_zh` | 中文全称，保留可确认的院区、分店、入口名 |
| `name_en` | 可读英文名；品牌、分店、馆区、街道保留辨识信息；不虚构官方译名 |
| `name_en_type` | `官方英文`、`来源已有英文`、`机器翻译`、`拼音转写` |
| `name_en_source_url` | 官方或来源已有英文的直接出处；机器翻译/拼音转写留空 |
| `address_zh` | 中文地址；街道/街区可写起止点或大致范围；无地址写“未知” |
| `source_name` | 来源名称（目录页写目录名与栏目/页码/条目名） |
| `source_type` | `政府目录`、`政府网站`、`场馆官网`、`品牌官网`、`行业目录`、`官方媒体`、`商业平台`、`地图平台`、`其他公开来源` |
| `source_url` | 直接支持该条名称/身份的具体页面；目录页需能定位到条目 |
| `collected_on` | 实际收集日期，`YYYY-MM-DD` |
| `review_status` | 固定 `待复核` |
| `notes` | 同名待确认、来源冲突、地址/英文待核、目录口径等问题 |

有出处时补充以下列（可留空）：

`name_zh_alt`、`name_en_alt`、`brand_or_parent`、`branch_name`、`attraction_level`、`cuisine`、`signature_dishes`、`intro_zh`、`accommodation_type`、`venue_type`、`nearest_metro`、`official_website`、`source_published_on`、`address_source_url`、`extra_source_urls`（`名称|URL`，分号分隔）、`name_en_note`、`source_category`（来源原分类，如米其林星级、A级景区等级）、`tags`（分号分隔）。

价格、营业时间、星级、预约要求等易变字段没有直接依据就留空，不猜测。来源页明确给出最近地铁站时才填 `nearest_metro`。

## 二级品类受控词表

- **餐饮**：本地菜馆、老字号、小吃店、早餐店、茶馆、咖啡馆、素食餐厅、夜市餐饮摊点、美食街、烘焙甜品、精致餐厅、其他餐饮。
- **酒店住宿**：酒店、度假酒店、精品酒店、民宿、青年旅舍、公寓式酒店、经济型酒店、其他住宿。
- **景点与文博**：景区、历史遗址、博物馆、美术馆、纪念馆、寺庙、教堂、清真寺、公园、动物园、观景点、主题乐园、文化场馆、其他景点。
- **街道与街区**：历史街巷、步行街、美食街、夜市、文化街区、滨水步道。
- **商场与市场**：购物中心、百货、奥特莱斯、传统市场、特色商业街、文创市集、免税店、特色商店。

“美食街”只用于街道级餐饮集聚区；商场、市场内的餐饮门店仍按门店记录。“特色商业街”只用于承担购物功能的商业街，与“步行街”“文化街区”按主要功能区分。景区等级写入 `attraction_level`，不写进二级品类；米其林/黑珍珠/必比登等写入 `source_category` 或 `tags`，不当作二级品类。

## 收集口径与方法

- 顺序：北京 → 上海 → 广州 → 深圳 → 成都 → 重庆 → 桂林；每城先做“行政区 × 品类”覆盖表，再按格收集。
- 范围：城市行政辖区，含中心城区和游客常去的外围区县（如桂林的阳朔、龙胜，北京的延庆、怀柔、密云，重庆的武隆、巫山等）。已查/未查区县在 `COVERAGE.md` 明确记录。
- 优先批量目录：政府文旅/文物/商务/园林主管部门的 A 级景区、博物馆、星级饭店、老字号、商业街、公园名录；其次是景区/机构官网、酒店集团门店页、品牌官网；商业榜单和公开页面只作补充并如实标注来源类型。搜索摘要只用于定位页面，不作唯一出处。
- 每个 POI 至少保留一个能支持名称或身份的具体来源页。目录页覆盖多条时，`source_url` 记目录页，`source_name` 写栏目、页码或条目名。名称、地址、英文名来自不同页面时，分别写入 `source_url`、`address_source_url`、`name_en_source_url` 或 `extra_source_urls`，不假定一个来源支持整行。
- 只读公开网页：未登录、未填表、未订餐/订房/购票、未调用接口或小程序、未调用付费接口、未新增凭据、未创建云资源；不采集坐标；不保存抓取原件、快照或运行日志。
- 本轮不做全库查重、不做冲突裁决、不逐条人工复检；近似重复、分店差异、榜单年份差异原样保留并在 `notes` 标记。

## 英文名处理顺序

1. 场所官网、官方英文页、品牌英文门店页或政府英文资料有明确名称：照录，标 `官方英文`，附 `name_en_source_url`。
2. 项目允许的其他公开页面有清晰英文名：采用，标 `来源已有英文`，附出处，不冒充官方。
3. 找不到已发布英文名：机器翻译或拼音转写，标 `机器翻译` 或 `拼音转写`，`name_en_source_url` 留空，并在 `name_en_note`/`notes` 说明。中文专名可保留拼音，通用类型译成英文；酒店品牌、分店、馆区、街道名称保留辨识信息。

## 校验

在仓库根目录运行：

```sh
uv run --locked python -B -m unittest knowledge/visitor/test_seven_city_poi.py -v
uv run --locked python -B knowledge/visitor/validate_seven_city_poi.py \
  knowledge/visitor/place-candidates/seven-cities-2026-11/*.csv
```

校验列名、行数、城市/编号/品类/二级品类、英文标记与出处、日期、来源字段和重复 row_id；不联网，不证明内容正确。任一文件失败退出 1。

同时传入七城 CSV 与 `all-cities.csv` 时，校验器额外检查：七城文件之间 `row_id` 不重复、`all-cities.csv` 的 `row_id` 集合等于七城并集、七城合计覆盖七个城市；此时总数按并集计一次，不重复累加。
