## 1. 分工与流程
| 步骤 | 谁 | 产出 |
| 1 派工 | Codex H | 批次 Goal：城市、记录组、目标条数、来源方向、禁止事项 |
| 2 采集 | DeepSeek | 按 §3–§5 写候选，本地跑校验器 |
| 3 提 PR | DeepSeek | 一批一个 PR，只改一个候选目录；正文按 §7 |
| 4 内容核验 | Codex H | 按 §6 抽检；PR 评论写 Verify: PASS/FIX/REJECT <head SHA> 和抽检表 |
| 5 审查合并 | 独立 R 会话 | 精确 head 上 CI 全绿 + Review: APPROVE <head SHA>，用 --match-head-commit 合并 |
| 6 晋级 | Codex H 派工，DeepSeek 执行，R 审查 | 候选转为 entries-v3 正式条目，另开 PR |
- DeepSeek 不改正式条目、校验器、SOURCES.md。晋级和到期复核 PR 例外，但必须由 Codex 派工。
- 清单外的来源类别、付费接口、需要登录的页面、Wikidata 批量查询（M4 条目 8：每天不超过 500 次并缓存），
  一律先问 JT。
- R 由独立会话担任，Codex H 不兼任。

## 2. 目标与计数口径
- 合格条数 = 所在批次已合并，且 Codex 抽检 PASS。FIX 修正后重新抽检；REJECT 的一条都不算。
- 每条只计入一个记录组：地点 / 门店 / 旅行知识 / 工具服务。
- 以下不计数，发现即删除：与基线或已有候选重复（含同一实体换名）；把同一事实拆成多条；
  只有名称、没有用途信息的地点。
- 每批更新覆盖矩阵（城市 × A–G 阶段 × 四个记录组，填条数）。派工优先补空格，已经饱和的格子
  （例如七城 A 级景区名录）不再加量。

## 3. 品类体系
3.1 记录组（互斥）
- 地点：七城写地点 CSV；其他城市暂用知识 JSON 的 place 字段，themes 含 attraction。
  包括景点、文博、公园、街区、交通枢纽、公共服务点。
- 门店：同上，CSV 用 餐饮 / 酒店住宿 分类；必须精确到具体门店，品牌总部地址不能当门店地址。
- 旅行知识：知识 JSON（visitor-candidate.1）；每条回答一个游客会问的具体问题。
- 工具服务：工具 JSON；官方网站、App、热线、人工服务台。
3.2 旅行阶段（每条必填一个主阶段）：A 出发前、B 入境抵达、C 城市与跨城交通、D 景点与家庭体验、
  E 餐饮住宿与日常、F 求助受阻、G 离境。格式 v2 合并前写在 notes 开头，例如 [阶段:C]。
3.3 主题：沿用现有 13 个枚举。放不下的在 notes 写 [主题缺口:住宿/餐饮/离境/日常]，
  不硬塞进不相关的枚举。
3.4 地点子类缺口：交通枢纽（机场 / 车站 / 口岸）和公共服务（游客中心、卫生间、母婴室、行李寄存），
  在格式扩展前先写成知识候选，place 填具体地点，不借用不相关的子类。

## 4. 字段与标记（格式 v2 合并前写在 notes / missing，用固定写法）
- [阶段:D]：必填，只写一个。
- [时效:高/中/低]：必填，等级见 §8。
- [复核:YYYY-MM-DD]：必填，按时效等级从 collected_on 起算。
- [依据:页面标题／小节或段落位置]：必填，Codex 凭它直接定位原文。
- [摘:……]：可选，不超过 30 字，只用于核对，不能作为正文。
- [英文:官方/来源已有/机器翻译/拼音/未知]：有 name_en 时必填；CSV 用现有 name_en_type 列。
- [儿童:年龄=…;身高=…;计算日=…;陪同=…;证件=…]：涉及儿童时必填，未知的项写“未知”。
- [护照:适用/不适用/未说明]：涉及预约、购票、实名时必填。
- [来源级:S1-S4]：必填，定义见 §5。
- [历史:适用期 …]：旧公告、活动信息必填，不能写成现行规则。
其他：
- summary_zh 用自己的话写，一条只讲一件事，不超过 600 字，不写来源没有说的内容。
- missing 列出游客最可能追问、但来源没给的项。
- 冲突写进 conflicts，注明双方说法、日期、URL，不做裁决。
- id slug 用 城市.主题.具体对象，不能用序号。
格式 v2（另开子票）：把上述标记改为结构化字段（journey_stage、record_group、volatility、review_by、
evidence[{url,locator,quote}]、child_rule、passport_applicable、source_tier、verification），
地点 CSV 扩城、加子类；新增 v2 校验器，v1 保持不动；只改 knowledge/visitor/**。

## 5. 来源分级
- S1：主管部门、交通运营方、场馆官网、服务提供方官网的正文。可写任何内容；在 SOURCES.md 登记后可晋级。
- S2：官方媒体、政府转载、具名采访报道。**v0.2 起只能佐证 S1 已写的内容，不能单独支撑任何字段**（v0.1 原为「可写规则和开放信息」）；须注明日期，写明资料局限。只有 S2 支撑的字段写成 null；整条没有 S1 支撑的条目不保留。对应 SOURCES.md「来源分级」。
- S3：商业平台（携程 / Trip.com / 本地宝等）、地图平台。v0.2 起对应 SOURCES.md「来源分级」的线索级。只能写地点是否存在、地址、营业时间、门店信息，
  不能写政策规则；只能作补充证据，不能单独支撑晋级。
- S4：其他公开来源、机构身份未核实的来源。只当线索，不能入库，也不能晋级。
- 禁止作为依据：搜索摘要、AI 生成页面、无署名自媒体；需要登录、付费或绕过限制才能看的内容；
  只有 JS 空壳、读不到正文的页面（记为缺口）。
- 签证和入境：只写 S1 主管部门的查询入口和咨询渠道，不概括资格、期限，不做法律判断。

## 6. 核验标准
6.1 等级
- V0：校验器 PASS，且 §4 必填标记齐全（grep 检查）。DeepSeek 自查，CI 复跑。
- V1：抽检，判定批次能否计数。Codex H 执行。
- V2：逐条全量核验，用于晋级或到期复核。Codex H 执行，之后 R 审查。
6.2 V1 抽检
- 抽样：每批随机抽 10% 且不少于 10 条；另外高风险条目全部检查：visa_entry、儿童规则、票价、
  开放时间、预约规则、外卡支付、S3 / S4 来源的政策类条目。
- 致命错误：编造（来源没有）；URL 打不开或不支持概括；城市、馆区、门店弄混；签证资格判断；
  把机器翻译标成官方英文；把历史信息写成现行规则；重复凑数。
- 一般错误：来源等级或类型标错；missing 漏掉明显缺项；日期字段填错；时效等级偏低。
- 轻微：措辞、slug、标记格式。
- 批次结论：
  - PASS：致命 0 且一般错误 ≤ 5%；
  - FIX：一般错误 5–15%，或致命 1 条。全批自查修正后在原 PR 推新 head，换样本重新抽检；
  - REJECT：致命 ≥ 2，或一般错误 > 15%。关闭 PR，不计数，下一批 Goal 针对指出的错误。
- 评论：Verify: PASS <head>；一行写抽样数、致命数、一般数；附逐条表（id / 判定 / 理由）；
  结论先行，不超过 10 行。
6.3 V2 晋级（候选 → entries-v3）：逐条完成 5 项：
  1. 来源已在 SOURCES.md 批准；
  2. 正文支持内容，中英文意思一致；
  3. 已查重；
  4. 设置 checked_on / expires_on；
  5. 走 R 审查和精确 CI。
  晋级后在候选里标注去向或删除。

## 7. 批次与 PR
- 每批 50–200 条。一个 PR 只改一个候选目录。分支 h/ds-<日期>-<批次>，从最新 main 开出。
- 不提交抓取原件、快照、日志，不写本机绝对路径。
- PR 正文：首行 Refs #<子票>；精确 base / head；条数（按记录组、城市、阶段）；校验命令和结果；
  高风险条目清单；缺口和冲突；声明“全部为候选，未转正”。
- 不同 PR 之间文件不能重叠。地点 CSV 的 PR 都会改 all-cities.csv，必须串行。
  索引文件只在单独的索引 PR 里更新。

## 8. 时效与复核周期
- 高（票价、开放时间、预约、临时公告、季节活动、班次）：14 天。
- 中（交通和支付规则、儿童票政策、热线时段）：30 天。
- 低（地点存在、地址、官方入口、机构名称）：90 天。
- v0.2 起（自 2026-12-09 那轮复核开始执行），再按支撑来源的稳定程度分档（见 README「复核期限分档」）：有明确有效期的官方规范或通知 90 天（或到有效期为止）；常设须知、指南页 30 天；临时公告和有起止日期的安排 7 至 14 天（或到结束日）。**两套分档取较早的日期。**
正式条目：失效时间按北京时间当日零点。复核时来源没有变化的只更新日期；内容变了的改写；
读不到或无法确认的下架，不能延期。
