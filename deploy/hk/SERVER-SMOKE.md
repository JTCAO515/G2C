# 香港应用发布后的 API 冒烟

每次香港 API/worker 切换后，S 在已登记的闲时维护段执行 10 分钟快速冒烟。使用原 C 合成账号发一句中文问答，独立且已准入的 G2C 合成账号做一次文字翻译、生成一次带起终点的滴滴链接。分别核对非空回答、非空译文和链接结构。服务端 5xx、超时或没有有效结果判 FAIL 并按原兼容回退包处理。准入或对账待核时记 HOLD 或 UNRUN，停发并核原动作。回答和译文的内容质量由 Q 后验。[JT 加速决定](https://github.com/JTCAO515/G2C/issues/495#issuecomment-7094822956)

1. 核当前和拟部署的精确 source/image、回退兼容性、香港授权、原账及全局排空。在同锁内用 `quick-preflight` 验证两份会话覆盖探测窗、插件会话属于翻译和打车共有的 G2C 名单，以及原 C 子额度。可在本轮首次启用插件前核对原账号准入，业务零调用。
2. 切换并独立读回现役。启用的翻译保留已核的 JT、C.zh、C.en 和原 99 名 G2C 主体。打车核对原 99 主体及服务器属主的 0600 Key 文件。回退到不支持这些配置的旧版本前恢复该版本可读取的原配置。
3. 持部署互斥锁，从同源运行角色执行 `python -B -m deploy.hk.server_smoke quick`。通过 stdin 提供 `access_token`、`translation_access_token`、`starts_at`、`ends_at`。最多 10 分钟，临时 C 上限沿用 ¥3，为翻译保留原最大占用，合计上限 ¥5。C 原账若仍有未结调用，保留占用、记 HOLD 并停止后两项。滴滴只发信息型链接，使用原日计数与免费额度。私有收据不输出正文、译文或链接。
4. 停发后读回全局在途及原账，并按原 `restore` 归还 C standing。保留未结费用和原回执。三项 PASS、原账与配置确认后通知 A。翻译继续启用。

## 完整服务端复测

原 `run` 和 `verify` 留作 Q 和服务端诊断使用。调用仍限实际窗口、M4 的既有香港测试环境、原身份和子账。按 [JT 的时段补充决定](https://github.com/JTCAO515/G2C/issues/495#issuecomment-7042305501)，窗口可在任何时段执行。正式基础 8、全国 16 和 JT 本人真机另记。

1. 切换前确认 ECS 免费试用资格、现役和回退镜像、在途及原账。用原 C 合成账号的合法短期会话做脚本 `preflight`。这一步校验签名、受邀范围、会话覆盖整个窗口和既有 C 子额，业务请求数为零。会话被拒绝或期限不足时登记 UNRUN。
2. 应用单次切换并独立读回现役 source/image。锁定该版本和空闲维护段，使用现有 `probes/application-deploy.lock` 串行执行脚本。使用运行角色内的 `python -B -m deploy.hk.server_smoke run`，stdin 从私有提供方读取 `access_token`、`starts_at`、`ends_at` 的 JSON。翻译开启时，preflight 和 run 还需独立的 `translation_access_token`，对应现有 G2C 插件内部名单中的合成账号。翻译请求和原费用回执按该会话的归属核对。运行输出放 0600 文件。已有版本可用独审通过的两文件原字节启动同一入口，不换应用运行镜像或启动配置。
3. 中英 Lio 和启用时的两项文字翻译共享单轮 ¥5 上限。运行先为两条翻译保留供应商原账的最大占用，再从同一上限内限制既有 C standing。关闭翻译时，C 可用的本轮占用为 ¥5。原 C 常设额度、归属和历史 hold 保留。中英各单次提交身份、能力、北京三日游。每项用 `/v2/lio/messages` 在原 C 账号内显式创建新会话，收到原默认会话的回执时记 UNKNOWN。每轮从发送阶段开始约每秒读取 `/v2/lio/timeline`，收到回执后按新会话读。每项核原 MESSAGE 回执和用户可见结果。北京三日游按同一原消息的 timeline 已保存行程或受保护的只读预览核验。结构必须有三天，每天至少一项可核为北京且未取消的活动。只读预览用原会话和原消息读回。只认逐项可信城市或可核实的完整地名，未分段的「长城」等通用称呼不能核同城市。汇总须保留两个原会话、原消息、结构读回引用和单条限时内的记录。缺少可信结构记 UNKNOWN，正文格式匹配只记诊断。最后用保留历史 `/v5/message-history` 分页读回原消息。首个 FAIL/UNKNOWN 后只保留原件，不重发。
4. 用 `verify` 读取 `events`（上述 JSONL 转数组）和同一现役 worker 同一窗口的无正文 `M4_MODEL_WIRE_TIMING` 行数组 `wire_logs`。RUN 与财务日志通过原 MESSAGE 绑定后的 attempt SHA 关联。要求一个原回答调用发出到供应商首包之间的连续区间在完整的读取记录内，该时长必须长于可避开完整 200 读取的最大间隔。没有重叠证据记 UNKNOWN。退出 0 为 PASS、1 为 FAIL、2 为 UNKNOWN、3 为 UNRUN。
5. 停止新请求、只读查原动作和全局在途。收尾同时报告保守占用、可计算 token/工具估算与实际实付。实付未核记 UNKNOWN，未结算原调用保留 hold。空闲和原账读回后，通过同锁执行 `restore`，stdin 接原 `restricted` 回执中的 `before`、`restricted`，加只读取得的 `drained_ledger`。归还仅恢复原 C standing，并保持全部尝试及 hold。收到不明确的状态先读原 cap 与账本。
6. 记录同源、逐项结果及原费用。完整复测出现内容质量问题时交 Q 和 S 按验收判据记录。

预检、执行和收尾使用同一个合成账号。禁止把 bearer、邀请码、回答正文或完整 worker 日志放入票评论或 Git。费用字段以 10^-7 元为单位，现金账单列为实付。
