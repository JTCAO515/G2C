# ADR-0005：主动式履约（V2）

- 状态：**用户决策 accepted**（JT 2026-10-27，见“JT 决定”）；**架构与模型选择 proposed**，按[影子模式规格](../v2/shadow-mode.md)验证后再收敛
- 日期：2026-10-27
- 适用版本：V2。V1 范围不变，[scope](../scope.md) 的 v1 Non-goals 与 [ADR-0001](0001-product-boundaries.md) 继续有效
- 关联：[ADR-0001](0001-product-boundaries.md)、[ADR-0003](0003-state-and-recovery.md)、[ADR-0006 会员分档与记忆保留](0006-membership-and-memory-retention.md)、[记忆规格](../memory.md)、[架构](../architecture.md)

## 背景

V1 是规划型 Agent App。V2 目标包括三块：后台运维 Agent、前台真实执行（预订 / 支付 / MCP 订单接口）、主动式履约。主动式履约指后台 Agent 持续监听对话与订单状态，识别需要处理的节点后建单执行；AI 承担大部分执行，人工只负责确认、验证和 AI 解决不了的环节。客户不进入客服队列，也不需要“转人工”。

现有边界：[scope.md](../scope.md) 将人工托底与后台运营 Agent 列为二三期方向，并写明 TypeSafe Jev 不作为首版栈；[architecture.md](../architecture.md) 写明反馈不扩为人工接管或运营 Agent。本 ADR 只为 V2 定方向，不改变 V1 / P2 的任何承诺或实现范围。

## JT 决定（2026-10-27）

1. **命名**：前台对客 Agent 为 CJ Agent；后台运维 Agent 暂定名 **JT Agent**。
2. **分工**：CJ Agent 负责规划、预订、支付、翻译、识图等对客能力，并把对话与业务事件交给 JT Agent。JT Agent 负责信号识别、建单、执行与回环。AI 承担大部分执行，人工负责确认、验证、外部核实和 AI 无法解决的问题。
3. **人工团队**：自建，前期 3–4 人；订阅量增长后再扩充。
4. **执行能力**：来自 V2 规划中的 MCP 与订单接口；前期由人工作为整体确认方，负责查单和对外电话核实订单。
5. **判断模型**：线上直接使用 TypeSafe Jev。数据驻留（境内 / 境外）在体量增长后再决定；脱敏、告知与同意等合规底线不随之推迟（见“约束”）。
6. **P0 紧急情况**：识别、应急号码和人工消息协助对**所有用户**开放，包括免费用户。承诺范围只到“协助”；陪同报警、联系使馆不在 V2 内。
7. **非紧急服务**：订单确认、餐厅预订、人工响应等只对付费订阅会员开放，具体档位见 ADR-0006。
8. **触达渠道**：V2 不回电，只用 App 内消息、前台弹窗和推送。WhatsApp 仅作 P0 消息超时未读时的备用渠道。App 内语音通话规划到 V3。
9. **SLA**：白天为北京时间 08:00–22:00，目标 5 分钟内人工响应；其余时间为夜间，目标 20 分钟。两者均为**内部目标**，不写入会员条款；实测达标后再评估是否对外承诺。
10. **透明度**：客户知道服务中有真人参与，但不知道真人在什么时候、哪个环节参与。真人做过的事在处理完成后告知客户，只给结论不给过程。花钱或改变行程的决策必须事先取得客户同意，并在处理中提示“正在处理 + 预计时间”。
11. **收费**：人工服务打包进订阅会员，不按次收费（方案 A）。当前阶段不以成本为约束。

## 架构（proposed）

```text
CJ Agent ──事件（outbox，稳定 ID）──▶ JT Agent（异步，不在对话关键路径）
  L1 信号识别  本地规则 + DecisionModel（Jev）类型化判断，每轮执行
  L2 研判      低置信度或高严重度升级到推理模型（Qwen）；去重、合并、连带影响分析
  L3 建单      Case：随机 case_id，只带最小必要信息
  L4 执行      版本化 playbook；每步标注 ai_auto / ai_draft_human_confirm / human_only
  L5 回环      结果交回 CJ Agent，以对话或推送告知；涉及资金或行程变更先取得用户确认
```

### 信号来源与分级

信号来源：对话内容、工具和订单结果、外部状态（航班、景区）、时间触发（例如入住日晚间仍无入住确认）。后三类是“主动”的主要来源。

| 级别 | 信号 | 处理要点 |
|---|---|---|
| P0 生命安全 | 遇险、急病、受伤、走失 | CJ Agent **同步**给出 110 / 120 / 119 和使馆信息，不等待工单；同时通知值班人员进行消息协助。召回优先，规则、Jev、Qwen 任一命中即触发 |
| P1 证件与资金 | 护照丢失、被骗、卡被冻结、支付异常 | 建单；AI 先给出报案和补办流程，人工核实 |
| P2 行程中断 | 航班变动、酒店不认单、交通停运及连带影响 | 按行程依赖分析受影响的入住、接送和门票 |
| P3 变更请求 | 改酒店、改日期 | AI 起草方案，用户确认后执行（接口或人工核实） |
| P4 AI 失效 | 同一意图多轮未解决、工具反复出错、负面情绪上升 | 静默建单，人工在后台解决，由 CJ Agent 告知结论 |

### 判断模型

- `DecisionModel` adapter：输入为脱敏后的对话片段与状态，输出为类型化决策加置信度（如 `signal_type`、`severity`、`needs_human`、`repeat_unresolved`）。Jev 为首选实现，Qwen（约束枚举输出）为对照和兜底实现，可通过配置切换。
- 级联规则：置信度达到按类校准的阈值即接受，否则升级到推理模型。P0 不依赖单一模型：本地规则始终运行，Jev 不可用时不得漏报。
- Jev 的性能与价格数据目前来自厂商和第三方，尚未在 G2C 数据上验证，所以模型选择保持 proposed。

### 最小披露

- Case 不携带用户 UUID，使用每个 Case 独立的随机 `case_id`。
- playbook 每一步声明所需字段的白名单。人工工作台默认打码；人工申请揭示字段时，系统先校验白名单，再限时揭示并写入审计记录。Case 关闭后揭示授权失效。
- 能由 AI 代办的就不向人工揭示（例如由系统带着姓名发邮件给酒店）。护照号默认不向人工揭示。
- 审计记录、Case 数据与揭示记录登记到现有清理体系（CLEANUP），随用户删除和注销一并处理。

## 约束

- **用户控制**：ADR-0001 与 ADR-0003 的“确认后写入”继续适用。JT Agent 和人工都不能绕过用户确认，直接改变正式旅程或发起扣款。
- **不可信输入**：对话、供应商返回和网页文本不能改变信号级别、playbook 权限或字段白名单。
- **Jev 合规底线**：发送前在本地脱敏，替换姓名、护照号、电话和精确位置；隐私政策写明对话会被分析且可能跨境处理，并取得单独同意；评估健康类信息（P0）作为敏感个人信息的处理要求；与 TypeSafe 确认数据保留期限，以及是否用于训练。具体合规结论需法务核实。
- **记忆**：系统不主动删除用户记忆；用户主动要求删除时必须删除（见 ADR-0006 与[记忆规格](../memory.md)）。

## 已确认 / 证据 / 待决 / 推断

- **已确认用户决策**：“JT 决定”1–11。
- **仓库证据**：scope.md 第 27 行（二三期方向、Jev 非首版栈）、architecture.md 模块表（反馈不扩为人工接管）、ADR-0001 用户控制边界。
- **外部资料（未验证）**：TypeSafe Jev 于 2026-09 发布，输出带置信度的类型化决策；CMU 论文 “JEV-as-a-Judge” 提出“置信则接受、不确定则升级”的级联方式。数据均为厂商或作者自报。
- **待决**：
  - WhatsApp 备用渠道的未读阈值（建议 10 分钟）；
  - P0 的值班安排与夜间轮值；
  - 告知用户的文案；
  - 交易链路，包括商户主体、资质、外国游客的支付方式、退款与差价承担。交易链路另起一轮决策，不在本 ADR 内。
- **Claude 推断（待验证）**：
  - 外部状态与时间触发类信号的价值高于对话识别；
  - “用户先于系统发现问题”的比例可以作为主动式履约的核心对外指标。

## 指标

MTTD（信号发生到被发现）、MTTA（首次触达客户）、MTTR（问题解决）、用户先于系统发现问题的比例、每单人工分钟数、各类信号的精确率和召回率。

## 取舍与风险

- 线上直接用 Jev，换来了上线速度和低延迟判断，代价是跨境合规与外部依赖风险。用 adapter 和本地规则兜底控制这两项风险。
- 3–4 人覆盖夜间 20 分钟目标，需要值班轮转，存在疲劳和单点风险。会员增长前保持内部目标，不对外承诺。
- 后台默认静默，只在有动作或有结论时触达用户，以控制误报造成的打扰。
- 本服务不替代报警与急救，用户说明与条款中需要写明。

## 验证与替换条件

先按[影子模式规格](../v2/shadow-mode.md)只识别、不行动，在真实标注集上校准 Jev 与 Qwen。如果 P0 召回率不达标、合规评估不通过或 Jev 不可用，就切换到国内模型实现，用户决策不变。

## 回滚

本 ADR 只涉及文档。撤销时 revert 对应提交；V2 尚无实现、数据或外部资源。
