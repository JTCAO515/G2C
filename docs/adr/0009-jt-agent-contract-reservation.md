# ADR-0009 JT Agent 契约预留：在 V1 契约上留出 V2 后台的扩展口

- 状态：proposed（Claude 起草，待 JT 批准后改为 accepted）
- 日期：2026-11-02
- Issue：[#399](https://github.com/JTCAO515/G2C/issues/399)
- 关联：[ADR-0003](0003-state-and-recovery.md)、[ADR-0005](0005-proactive-fulfillment.md)、[ADR-0006](0006-membership-and-memory-retention.md)、[ADR-0008](0008-message-send-permit.md)；M3 的 [#23](https://github.com/JTCAO515/G2C/issues/23)、[#26](https://github.com/JTCAO515/G2C/issues/26)、[#27](https://github.com/JTCAO515/G2C/issues/27)

## 背景

ADR-0005 为 V2 后台 JT Agent 定了方向，但没有任何契约层的落点。JT 在 2026-10-28 的共识稿（决策 Q1–Q26）里要求把预留限定为"纸面预留"：一份 ADR 加字段约束，不写 JT 代码，并计划赶在 #163（服务端发送许可）实现之前。共识稿随后被 JT 暂停；#163 在同日合并（PR #193），原窗口关闭。

M3（数据生命周期与反馈）正要定型记忆来源、删除链和反馈入口。这三块决定后续接入 JT 时是"加字段"还是"改已上线契约并迁移数据"，所以预留改到 M3 开工前完成。

**仓库证据**（`origin/main` 3502584）：

- ADR-0005 已写"CJ Agent 经 outbox 向 JT Agent 发事件，稳定 ID"，但没有 schema，迁移里也没有通用事件表。
- `SEND-V2.md` / `SEND-V3.md` 里的 outbox 指的是消息回执附带的投递义务（`cj_message_delivery`），不是 JT 事件流。
- 消息链路已有 `generation` / `last_sequence` 会话头（ADR-0008），以及 `cj_message_travel_reference`（`MESSAGE-TRAVEL-REFERENCE@1`）把消息关联到行程。
- 会话只有行程聊天一种；没有服务端主动发出的助手消息，也没有"服务"会话类型。
- `backend/storage-registry.json` 是私有存储的强制登记入口，清理链 `freeze_registry` 对没有清理钩子的登记项 fail-closed：`test_new_or_changed_registry_latches_gap` 显示新增 `cleanup_hook: UNIMPLEMENTED` 的条目会让清理操作变为 `blocked`。

## 决策

### 0. 范围

本 ADR **只预留口子**：不实现 JT Agent，不建表，不改 `contracts/**` 和迁移，不修订 ADR-0005。每个口子写清"不变量"和"由哪张票落地"。具体字段名、枚举值在各自票的契约 PR 里冻结，本 ADR 不冻结。

### 1. 事件 outbox（CJ → JT）

- CJ 的业务事务与事件写入**同一事务**；事件有稳定 `event_id`，投递语义为至少一次，消费方按 `event_id` 幂等。
- 事件**只带引用，不带内容**：会话 ID、`message_id`、序号、行程引用版本、事件类型、schema 版本、发生时间。对话原文由 JT 通过只读白名单视图按引用读取。这样事件表不成为第二份敏感数据副本。
- 需要预留的事件信息：新消息已接受、工具调用失败（含按会话累计的错误计数）、同一意图重复未解决（累计计数）、行程时间触发节点。计数在 CJ 侧计算，JT 不重新推导。
- 命名要与现有消息投递义务（`cj_message_delivery`）区分，避免同一个词指两件事。表名、游标形式留给契约 PR。
- 事件带保留期，随用户删除和注销清理（见第 6 条）。
- JT 宕机时事件积压在 outbox，CJ 主流程不受影响，CJ 不依赖 JT 的任何响应。
- **落地**：事件表本体不进 M3（没有消费者，建了是死数据）。M3 的约束是：#23 / #26 / #27 不得把"消息、记忆、反馈"写成无法产生稳定事件的形态（例如没有稳定 ID 的批量覆盖）。

### 2. 消息与行程节点的关联

沿用现有 `MESSAGE-TRAVEL-REFERENCE@1`，**不新增字段**。事件里带上消息已有的行程引用版本，JT 据此判断"入住当晚"与"行前"的严重度差异。

### 3. 服务端主动发出的助手消息

JT 的结论要经 CJ 以助手消息告诉客户，所以服务端需要能在没有用户请求的情况下写入消息。约束如下：

- 消息需要一个来源标记，区分"回应用户请求"和"服务端主动发出"。线上协议只暴露"助手消息"，**不暴露任何人工参与的信息**（共识稿 Q3）。内部审计另存授权来源（关联哪个后台任务、谁批准），不进客户端可见字段。
- **主动消息必须推进同一个会话头**（`last_sequence + 1`）。这保持 ADR-0008 的单一全序和"首次发送许可"不变量。代价是：主动消息会让客户端持有的预期会话头过期，在途的用户发送会得到 409 `SEQUENCE_CONFLICT`，按已有的 `reconcile_original` 恢复。这是预期行为，不是缺陷。
- 主动消息的写入同样走作用域行锁，与用户发送互斥。
- 主动消息不得引用或构成新的 NEEDS / 行程写入；任何花钱或改行程仍走"客户本人确认"（ADR-0003、ADR-0005）。
- **待验证**：上述与 #163 发送状态读取（加锁后一次读回执和会话头）的交互，要在落地票里用并发用例证明；本 ADR 不假定已成立。
- **落地**：M3 之后，随 JT 影子/编排阶段的契约票；M3 不实现。

### 4. "服务"会话类型

共识稿 Q12 要求"联系服务团队"是独立的即时会话。预留约束：

- 会话增加类型（行程 / 服务）。服务会话与行程会话**隔离**：不进入行程规划上下文，不触发行程记忆抽取，不使用 `travel_context` 引用。
- 署名由服务端按类型生成，不由客户端指定。
- 服务会话内容按共识稿 Q20 不脱敏，因此登记为**独立的敏感存储域**，查看留审计，随用户删除和注销清理。
- 现有 `contracts/feedback` 是单向反馈提交。将来"联系服务团队"需要双向即时消息时使用本会话类型，不在反馈存储里另建一套消息。
- **落地**：枚举位在 M3 涉及会话的契约票里一次留出；服务会话的业务实现不进 M3。

### 5. 后台人员的候选记忆

- 记忆来源类型预留一个"后台人员提出"的值，生命周期固定为**候选 → 用户确认后才生效**。候选状态不得参与检索、草稿生成或行程规划。
- 用户拒绝或不处理，候选不得生效；用户删除记忆沿用 ADR-0006（必须执行，并清理关联来源和派生内容，即 #26）。
- **待 #23 / #26 owner 确认**：现有记忆状态机能否直接表达"候选"，还是需要新增状态。本 ADR 只规定语义，不假定映射。
- **落地**：来源枚举位随 M3 #23 的契约 PR 留出；后台提出路径不进 M3。

### 6. 存储登记与清理（修正共识稿的做法）

共识稿原计划在 storage-registry 里"占位登记"JT 的存储。仓库证据显示这样做会让 #27 的注销清理被未实现的钩子阻塞，所以**改为**：

- **未提供的存储不登记。** 登记发生在存储真正提供（建表或接入外部处理方）的同一个 PR，并同时交付清理钩子，不允许先登记后补。
- JT 相关存储预留清单，供将来登记时逐项对照：事件 outbox、案件与用户的映射（vault）、服务会话内容、揭示与查看审计、飞书作为外部处理方。每项都必须有：服务端主体绑定、敏感字段清单、保留期、清理钩子、备份恢复 fence。
- #27 的清理链保持 fail-closed：将来任何新登记项缺钩子都使注销操作 `blocked`，这是期望的安全行为。
- 审计和案件数据"随用户删除一并处理"（ADR-0005）。注销清理不得以审计需要为由保留可关联到用户的明文；确需保留的合规记录要单独决策。

### 7. M3 的约束清单

| 票 | 约束 |
|---|---|
| #23 | 记忆来源枚举留"后台人员提出"位，状态语义为候选→用户确认（第 5 条）；写入路径产生稳定 ID，便于以后出事件 |
| #26 | 删除记忆须同时清理"候选"及其来源引用，不留下可被后台复活的残片 |
| #27 | 清理链保持对未提供存储不登记、对新增存储缺钩子 fail-closed（第 6 条）；不为 JT 预建登记项 |
| #24 | 离线行程，与 JT 无关 |

## 被否决的方案

- **现在建 outbox 表和 JT schema**：没有消费者，违反"最小充分修改"，且 JT 尚未获批开工。
- **在 storage-registry 占位登记 JT 存储**：会令注销清理 `blocked`，见第 6 条。
- **主动消息使用独立序号通道**：会破坏 ADR-0008 的单一全序和首次发送许可，增加客户端对账复杂度。
- **事件内携带对话原文**：产生第二份敏感数据，扩大清理面和泄露面。
