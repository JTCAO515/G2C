# Short native fixture source boundary

`FixtureSourceBoundary` composes the existing native holders for a B-selected
C preparation. There is no production caller or new read permission. Original
C AUTH/binding/pins, a current purpose/consumer qualification guard, the native
MESSAGE/Trip boundaries and the actual release reader are required host inputs.
No client chooses a database, owner, preparation or control path.

The acquisition order is the original release shared barrier, canonical MESSAGE
projection transaction, the genuine accepted-Trip `DecisionAuthority` holder,
then the canonical Memory transaction and its active scope/history fence. The
MESSAGE context's existing projection methods reuse its held transaction; no
nested history context or reverse Trip-to-MESSAGE acquisition is introduced.
The Memory binder sets the native 5s/10s timeouts before its scope/release hook.
The selected-Trip and pending-delivery checks use that already bound connection.

The source must have an actual accepted planning receipt for its complete native
RUN binding, remain the current selected Trip and have no queued/running owner
RUN or unacknowledged delivery. Missing Memory/history state is refused without
initialization. The private source frame records the actual release pair,
binding/source hashes, MESSAGE generation/epoch/sequence, Trip ID digest/version/
content digest, canonical Memory epoch and observed consent tuple or null.
Observed absence is not an authorization grant. A different state cannot silently
replace the expected frame for the same use.

`with_current` accepts only the exact expected frame and a bounded encoded local
projection. The trusted B callback can inspect the privately held accepted Trip
content; it must not return that private content to E. Current source and purpose
qualification are repeated before and after the callback and after the native
response holders exit. The frame itself contains no private Trip text, credential,
live context, processing permit or PASS claim.

## Validation and limits

The private PG controls create a signed native plan/edit/undo, then install the
actual HK release hook and current ACCOUNT-ADMISSION checker. They exercise the
real three competing M/Trip/Memory writer locks inside the projection, zero new
model calls, refusal of absent Memory state, current-source/consumer withdrawal
and native consent disable/enable/disable with unchanged Trip content. A consent
counter change is not hidden by matching booleans or the same Trip digest.
An authoritative local account-fence injection during the callback also
withholds its earlier bytes and prevents later reuse; this is not a claim of
running the entire physical account-erasure workflow.
Financial pins and the consumer-purpose predicate remain explicit local fixtures;
they do not prove real E registration or budget admission.

The actual current worker pool was independently observed as six, without any
configuration change. An additional private control uses a real six-connection
psycopg pool and the accepted native runtime lease, including an outer consumer
MESSAGE admission and fresh producer/consumer account checks. It measures a
peak of six and complete lease return. This single-operation test does not prove
arbitrary concurrent host capacity. Four holders plus transient authorization
reads cannot fit a pool of four; host activation must verify its actual complete
nesting/concurrency instead of silently raising limits or bypassing the pool.

This boundary is never held across model/tool/provider/network work. It is a
short source projection and one prerequisite for immutable-version admission,
not a complete fixture use. It does not enumerate all E surfaces, close E late
writes, scan disclosure, aggregate preparation costs or publish durable metadata.
A callback-created file is not a successful publication: later commit/return or
qualification failure must leave that original unpublished/query-only. Production
composition, full X01–X12 and paid E/F activation remain UNRUN.
