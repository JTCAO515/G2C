# 构建 48 真机七项核对

按 [发给 JT 的构建 48 复测步骤](https://github.com/JTCAO515/G2C/issues/702#issuecomment-7005038407) 与 [B 的放行通知](https://github.com/JTCAO515/G2C/issues/1048#issuecomment-7004930477) 核证，现役候选 `59cc874b5e87bd2e0451b81b144ee0bc2b15b6c9`。依七项编号分中英记录。记录每项大概时间，失败用截图和「问题记录」的复制内容定位；已有成功截图可辅助核证。

先记录 JT 的构建、语言、北京时间、截图与可见服务参考号。B 按对应时间和账号最小范围只读核对访问记录（路由、状态、请求号）和同一会话的 CID。发消息项再用原客户端 MID 对齐接收回执、原 RUN、同轮 timeline 正文、相关 Trip 及原账。账号隔离和实际候选版本由 B 核实。问题记录缺参考号时用其他同源原件核对，无法唯一绑定写 UNKNOWN。草稿仅比对真机前后可见状态。

| 项 | 核对原件 | PASS 标准 |
| --- | --- | --- |
| SM01 打开 App 恢复 | 打开时间及恢复结果，旧 CID，原 timeline 页或恢复所用的原接收回执 | 回到已建立的同一对话，原消息可见，无此次恢复触发的新 MESSAGE |
| SM02 新对话问答 | 发送前后截图，新 CID/MID，接收回执、RUN、原 timeline 正文 | 新 CID 与旧 CID 独立，对 JT 实际提出的问题有正确、完整、用对应语言且实际可见的回答 |
| SM03 历史 | 打开历史列表的时间及结果，旧、新 CID 与对应原 timeline 或回执 | 列表可见，旧、新会话记录与各自原件相符；若点开某条，再核打开的 CID。单独的 200 无法证明列表正确 |
| SM04 后台或锁屏返回 | 实际采用的转场、返回时间、草稿前后状态、恢复原读与 MESSAGE/attempt 差值 | 锁屏或切后台 10 秒后返回，原对话、已答内容和未发草稿连续，无重复发送或重复欢迎语。记录实际方式 |
| SM05 身份 | 原 MID/RUN、可见正文和实际截图 | 对同轮提问用正确语言明确说明 Lio 身份，静态欢迎语不计 |
| SM06 能力 | 原 MID/RUN、已审同源正文、实际截图 | 有具体肯定的可用能力。订票和付款限制允许保留，否认规划、裸标题、引文或欢迎语不计 |
| SM07 三日游 | 原 MID/RUN、完整可见正文或日卡、原 Trip／版本／保存回执（若发生） | 北京第 1、2、3 天都有明确可执行活动及日内时段或顺序，正文可见。裸地点、追问、截断或空卡 FAIL。若宣称保存，须核实同一原动作的正式写入；无日期预览按实际模式核零正式保存 |

同时记录可证的首进度、首正文及完成时间，三栏费用保留保守占用、已知估算、实付。独立记录可见回答、原 RUN、写入和计费，不把完整可见正文因内部格式或费用状态改判为无回答。无正文或缺行程判 FAIL；已执行却缺唯一原件判 UNKNOWN；未执行为 UNRUN。首个产品 FAIL/UNKNOWN 停后续并交对应线，不要求 JT 重发。全过才通知 L。
