# 构建 52 发布验收清单

依据 [#1341](https://github.com/JTCAO515/G2C/issues/1341) 和 [JT 发布决定](https://github.com/JTCAO515/G2C/issues/495#issuecomment-7090627025)。A 走模拟器和真机，B 部署、跑服务端冒烟并核对原件，L 跑基础 8 条，C 跑全国 16 条、核证并判定。JT 本人的构建 52 真机走查单独登记。

## 执行与证据

- A 登记 TestFlight 构建 52、App 提交、系统版本、App 语言和内部账号别名。B 登记香港实际部署的 source、image、时点和冒烟结论。所有证据须对应实际执行版本。候选变化后复核受影响项。
- B 部署后的真实自动冒烟全过，含基础链路、千问中转和滴滴链接检查。B 核对已批准内部名单的翻译长期开放状态和现有鉴权资格。仅用既有授权账号、窗口和额度。
- 每项记录时间和时区、操作、界面结果及去敏截图或问题记录参考号。B 按账号、时间及原始引用只读定位同轮请求，提供必要的路由、终态、内容或摘要和原账。C 核对 UI 与原件一一对应。公开评论只放可分享的结论和去敏证据链接。

## 部署冒烟的行程判定

按 [JT 最新决定](https://github.com/JTCAO515/G2C/issues/495#issuecomment-7094664500)，B 核同轮「北京三日游」结构。恰好 3 天，每天至少 2 个带地名的具体活动，结构即 PASS。已核清的结构不达标记 FAIL，UNKNOWN 用于费用或状态无法核清。地名不够具体登记为回答质量问题，交 L 并由全国 16 条按冻结判据评估。地点精度本身无需回滚。

## 基础链路

中英文各执行七项。先用模拟器检查，再用构建 52 真机核证。另列 JT 本人真机证据。按 [JT 最新决定](https://github.com/JTCAO515/G2C/issues/495#issuecomment-7094664500)，M4 使用系统默认字号。最大字号问题登记到 M5。

| 项 | 怎么测 | 看什么证据 | PASS |
| --- | --- | --- | --- |
| 01 启动恢复 | 已有对话留未发草稿，强制关闭 App 后重开。 | 转场时间、前后界面、旧 CID、原 timeline 或恢复读回。 | 同一旧对话、原消息和草稿恢复，无此次恢复触发的新 MESSAGE。 |
| 02 新建问答 | 开新对话，用当前语言问北京是不是中国的首都。 | 新旧 CID、原 MID、接收回执、RUN、原 timeline 正文和真机结果。 | 新 CID 独立，有正确、完整且同语种的可见回答。 |
| 03 历史 | 从历史列表分别进入旧对话和第 02 项的新对话。 | 列表、进入时点、各自 CID 与原 timeline 或读回。 | 两个对话均能打开，原消息各自正确。 |
| 04 后台／锁屏 | 保留已有回复和未发草稿，后台 10 秒后回，再锁屏 60 秒后回。 | 两次转场的时点、前后界面、同 CID 原读与 MESSAGE/attempt 差值。 | 两次都恢复原对话和草稿，无重复发送或重复欢迎语。 |
| 05 身份 | 问「你是谁」／“Who are you?”。 | 同轮 MID/RUN、原正文和可见结果。 | 用提问语言说明 Lio 身份，有实际正文。 |
| 06 能力 | 问「你能做啥」／“What can you do?”。 | 同轮 MID/RUN、原正文和可见结果。 | 有具体、肯定的可用能力。可说明使用限制。只有引文、裸标题或否认能规划均不通过。 |
| 07 规划 | 问「北京三日游」／“Plan three days in Beijing”。 | 完整可见正文或日卡、原 MID/RUN。若宣称保存，再查同一动作的 Trip、版本和回执。 | 北京三天各有可执行活动和日内时段或顺序。裸地点、空卡或截断判 FAIL。无日期预览核零正式保存，宣称保存须原件证实。 |

欢迎语、ACK 或 HTTP 200 单独都不能证明通过。可见回答、RUN、写入和计费分别核证。内部格式或计费问题单列，保留用户实际看到的有效正文。

## 千问翻译与本机兜底

按 [#1234](https://github.com/JTCAO515/G2C/issues/1234) 使用自备中英文短句和清晰样图。模拟器核入口、权限和界面，构建 52 真机核话筒、相机、在线结果与自动兜底。

| 项 | 怎么测 | 看什么证据及 PASS |
| --- | --- | --- |
| MT01 文字，中→英／英→中 | 分别输入或粘贴测试句，提交后复制和朗读译文。 | 两方向各有正确可见译文，复制和朗读可用。B 核香港中转、千问成功终态和该次原计量，界面来源一致。 |
| MT02 语音，中→英／英→中 | 用设备麦克风分别说测试短句，结束录音并等译文。 | 两方向的可见听写和译文均正确。B 能核同轮 ASR、翻译及费用。502、只有 ASR INTENT 或未达翻译均不通过在线项。 |
| MT03 拍照，中→英／英→中 | 用设备相机分别拍中英文测试材料，观察原文识别、分段与译文。 | 两方向均拍摄成功并显示对应的正确译文。B 核同一原请求的成功、来源和费用。相册或合成材料只能作补充。 |
| FB01 断网 | 预装 Apple 语言包，真机关闭 Wi-Fi 和移动数据，再提交测试文字。 | 自动显示有内容的本机译文，标明「离线翻译」或对应英文。记录离线状态、时间、结果及 B 原账的零新增上游调用。 |
| FB02 额度用尽 | 用 B 提供的既有授权、配额已耗尽的测试状态，联网提交测试文字。 | 原香港回执证明额度拒绝，设备自动显示本机译文及来源。B 核拒绝后零新增上游尝试。禁止刷请求耗尽额度。 |
| FB03 服务出错 | 用 B 批准的隔离方式在真机触发一次服务异常。 | 同轮服务错误与客户端路径可对上，界面自动显示本机译文并标明来源。原 UNKNOWN 或费用如实留存，零重发。 |

三项兜底各执行一次并分别留证。缺语言包、手动切换、空结果或仅提示错误均不通过。在线模式独立判定。保留权限拒绝和缺语言包的本地回归。服务异常使用真实同路故障证据，夹具不计真实成绩。按 B 的隔离方案执行，避免影响其他用户。

## 正式判定与分发

1. C 按项、测试方向和证据层级记录 PASS、FAIL、UNKNOWN 或 UNRUN。已执行但未能绑定唯一原件记 UNKNOWN，证据显示不符合标准记 FAIL，尚未执行记 UNRUN。真实结果与夹具分列。
2. C 正式放行前，核对 [#1334 的 A 线六项门槛](https://github.com/JTCAO515/G2C/issues/1334) 全部 PASS，并保留各项证据链接。六项为千问三模态真实开通、滴滴真实估价与跳转及行程入口、本地协助 v1、构建 49–51 已知问题与崩溃闭环、多机模拟器兼容与首次登录、JT 文案与同源更新。
3. 在 [#1341](https://github.com/JTCAO515/G2C/issues/1341) 结论先行，附逐项证据索引。检查 JT 本人真机走查、内测名单与短码登录、中英指南及反馈渠道、App 内／TestFlight／#702 三处同源说明。C 的验收框按真实证据勾选。
4. 适用发布项全部通过后，才在 [#702](https://github.com/JTCAO515/G2C/issues/702) 写「构建 52 可以分发给内部测试者」。进度原地更新 [#759 C 线状态](https://github.com/JTCAO515/G2C/issues/759#issuecomment-6973065746)。
