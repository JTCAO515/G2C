## 请求与正式写入

- 服务端从会话取得 principal；每个资源和引用都核归属。请求追踪标识与业务动作幂等标识分开，模型 attempt 再独立记录；名称/类型由契约定义。
- 消息接收后可无 Trip；已有旅程绑定/解除/切换要可见，多旅程歧义先询问。用户/同伴、临时条件/长期偏好分开。
- Proposal 发布后不可原地改；接受绑定具体内容和预期 Trip 版本。事务同时核归属、候选状态与版本，写正式状态和回执。旧版本返回冲突，不能自动覆盖。手动保存与 AI 接受共享同一完整性入口。
- 动作的幂等作用域包含 principal、操作种类和稳定标识；同标识同输入返回原结果，不重复副作用；同标识不同输入应冲突。保存多久、过期如何查询由各 owner 明确，不能给无限去重承诺。
- 未收到响应只说明结果未知。客户端保留原动作标识查询/重试；恢复执行先对账。付费 provider 调用未知时进入待核对，不能因工作流可重试自动重复扣费。

## 运行、事件与取消

RUN 契约须规定稳定 run/message/conversation 标识、单运行有序事件、序号/去重、快照游标、分页和保留/过期语义。重复事件可安全忽略，缺段/游标过期转快照重同步；未知事件与客户端版本不匹配要显式处理，不能当成功终态。

事件流是状态通知，不是唯一事实源。SSE 中断不代表运行失败，客户端查原运行；明确服务器接受后再显示已接收。运行仅有一个最终状态，晚到正文不能复活已取消/终止运行。最终事件/快照列明已提交的业务变化、待核对与失败部分。

取消阻止尚未开始的后续步骤；已提交副作用仍可查询，不假装回滚。同聊天顺序、并发提交/账号切换冲突、重启投递恢复由 MESSAGE/RUN 共同规定。发布任何新回复/方案前复核相关账号、记忆、来源与旅程版本；失效上下文的在途结果不再成为有效结果。

## 错误与未知语义

| 类别 | 对用户/消费者的含义 | 处理原则 |
|---|---|---|
| 输入/范围不支持 | 用户可纠正或缩小范围 | 指出具体字段/约束，不补造默认成功 |
| 认证/权限/归属 | 会话失效或无权访问 | 恢复会话/拒绝；不泄露他人资源存在性 |
| 版本/幂等冲突 | 已有更新或动作输入不一致 | 读最新版本，展示差异后重新确认 |
| 额度/准入 | 尚未派发或受限 | 说明可恢复条件；不绕限额或偷偷降质 |
| 工具无结果 | 查询完成但未命中 | 与网络失败、无权限、数据未知区分 |
| 超时/依赖不可用 | 局部或整体暂不可用 | 保留来源状态；重试须确定是否有副作用 |
| 接收/提交/费用未知 | 结果尚无法核定 | 查询原动作/attempt；不换标识重发 |
| 部分成功/清理失败 | 已有提交与未完成部分并存 | 按回执列清，保留失败恢复，不报全成或全撤销 |

BASE 后续明确 HTTP 状态映射、机器可读类别、可重试性、request_id 和安全详情；RUN 统一流内失败与终态。文案中英对等，不把内部栈/秘密暴露给用户。正常、失败、未知、冲突、撤回、重复、晚到及账号切换都是契约样例，不只是 happy path。
