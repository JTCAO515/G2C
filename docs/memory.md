# 首批完整长记忆规格

行为要求已确认；数据模型、API 与存储实现待验证。责任链：组件验证 CJ-003 [#3](https://github.com/JTCAO515/G2C/issues/3)；条目与及时保存 CJ-011 [#12](https://github.com/JTCAO515/G2C/issues/12)；编辑/启停 CJ-019 [#17](https://github.com/JTCAO515/G2C/issues/17)；持续沉淀/摘要检索 CJ-020 [#23](https://github.com/JTCAO515/G2C/issues/23)；删除 CJ-021 [#26](https://github.com/JTCAO515/G2C/issues/26)；注销 CJ-024 [#27](https://github.com/JTCAO515/G2C/issues/27)。

## 内容与权威

跨会话、App/服务重启和不同旅行保留静态事实、经历与偏好。每项都是可管理的独立条目，以结构化分组组织；详情包含来源、大致发生/记录时间、适用人/旅行/期限、确认与启用状态、版本。字段是设计需求，不是已存在 schema。

正式条目由 CJ 管理，摘要、索引、向量与 soul.md/character.md 如存在，只是可重建派生视图。中英表达命中同一事实，不分别复制成两套权威记录。

临时预算/本次腿伤等条件与长期偏好分开；同伴信息不能写成本人事实。行为推断保持候选，生成的行程不能反向制造用户偏好。合成例子“不吃辣”“腿伤”不代表 JT 个人事实。敏感信息仅在明确范围处理，不从一次显式保存推导无限历史采集或主动 outreach 权限。

## 收集、保存与使用

首次和后续交流以 2–3 个相关问题渐进收集，允许跳过，不用长表单阻塞帮助。直接陈述/明确保存请求进入及时增量路径；授权内的多轮对话结束后摘要提取补充经历和候选偏好。会话结束判定、游标与去重边界由 MESSAGE/MEMORY 固定，不能等会话结束才首次记住明确事实。

| 入口 | 交互与保存条件 |
|---|---|
| 明确陈述或主动新增 | 明示本次保存内容/范围，展示真实保存回执；只有持久提交后显示成功 |
| 多轮归纳/行为推断 | 显示可编辑的候选确认气泡；用户确认后才成为有效长期条目 |
| 历史整理 | 用户可查看并启停来源范围；显式保存单条不等于授权整理全部历史，整理开关也不等于确认每个推断 |
| 纠正/编辑 | 展示新值与保存状态；版本检查后替换有效值，保留必要来源关联；旧提取不覆盖新值 |

UI 区分待确认、保存中、成功、失败与结果未知。保存失败不显示“记住了”；未知时查询原动作；重试复用原标识。正文回答生成失败与记忆已保存可以同时发生，分别回执。

保存成功的新版本须影响同一会话**下一次回答/规划**，以及新会话和另一旅行；检索结果进入模型前按最新授权/启用/删除/版本过滤。不能仅在 UI 显示新值、模型仍用旧摘要或原消息。相关上下文有界，非相关历史不全部塞入 prompt。

## 管理、并发与删除

记忆 Tab 提供分组列表、详情来源/大致时间、新增、编辑、单条启停和整条删除；账号设置在该 Tab 内。停用立即排除后续上下文，重新启用须校验条目仍有效。编辑/启停/删除以预期版本提交，冲突显示并允许重新审阅；原 owner 的后台提取用来源版本校验，不能覆盖用户较新的纠正。

删除包含两项独立结果：**立即停止使用**与**关联存储清理**。先提交撤回依据/版本屏障，阻断检索、原消息拼接、摘要、缓存和晚到写入；再对 CJ 可控制的记录、摘要、索引、缓存及必要执行 checkpoint 清理，显示清理中/完成/失败和可恢复状态。软删除或 UI 消失不等于清理完成。

保留原聊天不允许重提取复活被删偏好；索引重建、进程重启、备份恢复均须遵守撤回依据。新明确重新保存采用新来源。已发给模型的请求不能撤回；受影响在途结果不得发布为新有效回复/方案。历史已展示内容、供应商留存、备份和断网设备的能力边界须在用户说明中准确披露，不承诺即时抹除不可控制副本。

账号注销覆盖新产品全部域及设备缓存/执行留存；离线设备按确认的期限和重连清理，不承诺即时远程擦除。首次不额外承诺独立聊天/旅程删除入口。旧产品数据不在本轮操作范围。

## 验收链

CJ-025/026/028 [#28](https://github.com/JTCAO515/G2C/issues/28)、[#29](https://github.com/JTCAO515/G2C/issues/29)、[#32](https://github.com/JTCAO515/G2C/issues/32)对当前候选分别验证：

1. 两账号、中英表达：明确保存/归纳确认 → 真实库条目 → 详情/回执 → 同会话下一轮 → 新聊天 → App 与服务重启 → 不同旅行，实际影响回答/规划。
2. 临时与长期、用户与同伴、推断与事实、生成行程与真实决定分别验证；基础聊天摘要可无 Trip，真实接受/修改旅程来源后续接入仍需完整组合验证。
3. 编辑/停用/删除与旧提取/缓存召回/在途回答竞态；同时检查库、索引和**实际模型上下文**，旧原文/摘要重建不能复活。
4. 保存失败/未知、重复投递、并发版本冲突、清理失败恢复和备份撤回重放；另一条记忆和另一账号不受影响。
