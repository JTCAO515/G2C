# C1 local foundation probe

This small SwiftUI app exercises BASE@1.0 through the official generated client and URLSession transport. It is an engineering probe, not the product shell or a replacement for CJ-004's rendering/auth selection. No Agent, memory, Auth or business data is included.

Tested: Xcode 27.1 (27A9275), Swift 6.4, arm64, dedicated iPhone 17 Pro simulator on iOS 26.5. Package/app deployment target iOS 17 and macOS 14 are experiment settings only; they do not decide product support. Older runtimes, x86, physical device, signing/archive and App Store are UNRUN.

From repository root:

```sh
. ./scripts/env.sh
uv sync --locked
./scripts/generate.sh --check
./scripts/swift.sh test
./scripts/swift.sh build --product CJProbe
CJ_ENV=local ./scripts/start-local.sh 18765
# Another terminal, API remains running:
CJ_ENV=local CJ_API_BASE_URL=http://127.0.0.1:18765 uv run --locked python scripts/check_wire.py
./scripts/build-ios.sh YOUR_SIMULATOR_UDID
```

Build command only compiles. Install `.local/DerivedData/Build/Products/Debug-iphonesimulator/CJProbeApp.app` into an authorized isolated simulator, then launch `space.go2china.foundation.local` with explicit environment `CJ_ENV=local` and `CJ_API_BASE_URL=http://127.0.0.1:18765`. Xcode scheme does not embed a default API address. XcodeBuildMCP `launch_app_sim` accepts these in `env`; setting session defaults alone did not inject them during the tested `build_run_sim`. In Xcode, add them to Run / Arguments / Environment Variables for a local session. Do not put secrets in the scheme.

The only accepted target is explicit HTTP IPv4 loopback with a port; missing/other environment, external host, userinfo or query fails before dispatch. The local-only app has `NSAllowsLocalNetworking`, no broad ATS bypass. The transport uses ephemeral URLSession without cookies or URL cache. It checks the generated response header against body request_id and requires a UUID; decode/trace/transport failure remains visible. All HTTP redirects are refused by the URLSession task delegate before following, including loopback-to-loopback redirects. Redirect responses surface as explicit HTTP 3xx rejection without requesting the destination or inventing a trace receipt; CLI exits 1. A non-redirect 3xx that cannot decode the canonical envelope remains an explicit unavailable/invalid response failure. No automatic retry is implemented. The UI task is cancelled with view lifetime; cancelled late results do not update the screen.

For a real 404, relaunch with `CJ_API_BASE_URL=http://127.0.0.1:18765/missing`; the generated operation reaches an unmatched route and decodes the canonical error envelope. For unavailable state, stop the owned API and relaunch with the original URL. No server failure-mode query or mock business route is shipped.

`Package.resolved` is the editable Swift lock. Xcode's workspace mirror is generated by `build-ios.sh`; do not edit it independently. Generated API source is checked in for consumer review and is regenerated only by `scripts/generate.sh`. Package and Xcode build/dependency outputs stay in `.local` / `ios/.build`. Tool-managed XcodeBuildMCP logs are external to these outputs and are referenced in evidence.

Run `uv run --locked python scripts/check_redirects.py` after building `CJProbe` for the focused redirect regression: two IPv4-loopback listeners, five redirect statuses, disallowed `localhost` and different-port loopback destinations, zero destination requests. See `evidence/C1.md` for original steps/results and `evidence/C1-R1.md` for the narrow repair, first failures and limits. C2 remains unprovisioned; no device-reachable HTTPS, real auth/database or product acceptance is claimed.
