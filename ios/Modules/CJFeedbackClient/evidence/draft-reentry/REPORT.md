## Minimal repair

Only FeedbackPresentation.swift changes production behavior (6 added lines/1 removed).
An accepted `edit` or `associateContext` now rotates the existing preparation request,
clears its started marker and invalidates the client's captured operation. These are
existing lifecycle mechanisms, not a new state abstraction. `prepare` already rechecks
request/lifetime after client.begin/currentBinding; it therefore returns nil after an
accepted callback edit. New editor text/association remains visible/editable, original
remains nil, no record is appended and no request is sent. A later explicit click
captures that current draft. The first preparation never dispatched, so this is not
replacement-ID retry of an uncertain submitted action.

Edits attempted after original is frozen or while busy still fail the existing canEdit
guard. They do not retire original-action queries, mutate original bytes or imply newer
text was submitted. Changing association is fenced too; edit-away-and-back (ABA) also
retires preparation. Nothing silently re-encodes a frozen action or clears unknown data.
